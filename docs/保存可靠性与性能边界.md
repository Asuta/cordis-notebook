# 保存可靠性与性能边界

## 笔记保存

每篇笔记有独立的服务端 `revision`。旧文件缺失该字段时按 0 读取，首次成功更新后持久化新版本。`PATCH /api/notes/:id` 和 `DELETE /api/notes/:id` 必须在 JSON body 中传入读取时的 `revision`；缺失或过期返回 409，错误 `code` 为 `NOTE_REVISION_CONFLICT`。宿主 HTTP 层和客户端请求层保留该标识，前端仅将这一类 409 视为版本冲突；格式插件暂时不可用等其他错误仍可重试。校验在串行写入队列内部执行，失败不改变内存或磁盘。可信进程内调用 `notes.update(id, patch, expectedRevision)` / `remove(id, expectedRevision)` 仍兼容省略版本；处理外部请求时必须传入版本。

前端保存中继续输入会继承自己的成功写入版本。其他页面写入导致冲突时，保留本页草稿，停止自动重试，并显示“另存为副本”。副本通过 `POST /api/notes` 的 `{type, fields}` 一次校验并原子创建，保留原笔记。旧草稿恢复不会冒用服务端最新版本；删除后的孤立草稿可以恢复为新笔记。冲突处理目前提供另存副本，没有逐段自动合并。

公共文件写入位于 `shared/persistence.js`，宿主通过 `ServerRuntime.writeSnapshot(file, snapshot)` 提供给后端插件。笔记、画图、画布、图片供应商配置与工作台配置共用它：同进程同路径串行、临时文件完整写入后替换、Windows 短暂占用有限重试、失败保留旧文件并清理临时文件。这不是多个独立进程写同一目录的数据库锁；各 checkout 仍应使用自己的数据目录。

## 笔记历史与回收站

笔记存储从旧数组兼容升级为 `{format:'cordis-notebook-store',version:1,notes,history,trash}`。保存前的版本与删除记录在同一原子快照中提交；失败不改变内存中的正文、历史和回收站。历史每页最多 50 条，总量最多 32 MiB，最旧版本先淘汰；回收站只由用户显式永久删除，不自动清空。当前实现仍整体写入快照，历史上限约束额外开销，不是增量数据库。

恢复历史要求当前服务端数值 revision，创建一个更高 revision 的版本，并保留恢复前内容。回收站按原 ID 恢复并提高 revision，防止删除前的旧标签页静默覆盖。父关系无效时恢复为顶层页，原子提交前再次检查整棵树。正文格式插件未启用时恢复拒绝，原记录保留。JSON 内容备份不包含历史与回收站，完整备份需保留本 checkout 的应用数据目录。

数据库行编辑和行内公式存在独立的未提交输入时，通过 notebook/before-action、plugins/before-stop 以及 beforeunload 保护。点击取消代表放弃这些表单输入；保存/完成后进入通用笔记的草稿和自动保存流程。

## 工作台历史

会话按 `.workbench/conversations/<id>.json` 单独保存。启动时自动迁移旧 `conversations.json`，全部文件落盘后才发布 `.format.json` 标记；旧文件保留用于备份，不再作为活动写入目标。中断的迁移可重试，损坏文件会报错而非静默替换为空历史。

同一会话尚未落盘的更新只保留最新状态，最多一个正在执行的写入。保存失败会通知页面，待写状态保留，后续更新或关闭时重试；关闭会等待最终写入。不同工作台实例仍不能共用一个数据目录。

网页每 3 秒读取 `/api/state?summary=1` 的应用状态与会话摘要，不再传输所有历史。打开会话通过 `/api/threads/:id` 读取最近 20 轮，`before` 向前分页，`since` 对相同 revision 返回 unchanged。分页以完整轮次为单位，保留消息和工具轨迹的关系；“加载更早的对话”逐页显示历史。SSE 推送当前轮次或最近一轮，不重发全部历史。客户端按分页位置合并显示顺序，重叠记录独立按 revision 采用较新内容，避免先收到 SSE 时把最新一轮排到历史前面。兼容旧调用的 `/api/state` 仍返回完整详情。

目前启动仍把所有会话读入内存，单个会话写入仍包含该会话全部历史；分页按轮次而非字节限制，特别大的单轮仍可能较大。此轮改进消除的是跨会话重复序列化和常规轮询的历史传输，不代表模型响应时间下降。

## 模块与验证

- 工作台：`conversation-store.js` 负责持久化；`conversation-view.js` 负责公共摘要和分页；`public/thread-cache.js` 合并摘要、分页和 SSE；`page-bridge.js` 管理页面身份与调用；`tool-router.js` 路由工具；`task-state.js` 管理重启恢复与轨迹通知。
- 自由页面：`history.js` 管理撤销，`uploads.js` 固定异步上传目标，`clipboard.js` 管理容器粘贴和拖入，`view.jsx` 渲染工具栏。块页面和自由页面继续各自拥有自己的文档模型。
- `pnpm typecheck` 检查公开契约，并以 strict checkJs 检查 `tsconfig.runtime.json` 列出的实际 JS 实现；尚未覆盖整个仓库。
- `pnpm test` 包含版本竞争、持久化迁移/合并/失败恢复、分页竞态、编辑器交互和开发导航检查。`pnpm test:browser` 另跑真实 Chromium 产品回归，包括四格式保存刷新、跨页冲突与副本、图片粘贴、笔记 HMR 和插件启停；使用隔离数据，无模型 API 调用。
- 插件数量由 `pnpm docs:inventory` 生成 [应用插件清单](应用插件清单.md)，测试检查过期；开发导航的全部 task/template 会解析真实文件、选段和服务。
