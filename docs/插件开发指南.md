# 留白插件开发指南 · API v1

宿主项目的启动、架构和维护流程见 [项目接手与维护指南](项目接手与维护指南.md)。本文介绍第三方 API v1 插件；开发内置功能请另看 [内置插件服务契约](内置插件服务契约.md)。

## 1. 插件结构

一个插件同时可以包含前端和后端，二者分别加载。后端就绪后前端才挂载。

```text
my-plugin/
  manifest.json
  server.js
  client.js
```

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "apiVersion": 1,
  "description": "插件用途",
  "dependencies": ["layout", "notes"],
  "server": "server.js",
  "client": "client.js"
}
```

至少有一个入口；纯前端或纯后端可省略另一入口。id 使用小写字母开头，后续允许字母、数字和连字符，长度 2–50。版本使用 x.y.z。依赖必须先安装、先启用，不会静默启动未启用依赖。当前不解析依赖版本范围。

## 2. 前端入口

```js
export default function (ctx, sdk) {
  const panel = sdk.el('section', { class: 'extension-panel' })
  const button = sdk.el('button', {}, '执行')
  const output = sdk.el('pre')
  panel.append(button, output)
  sdk.mount('panels', panel)
  sdk.listen(button, 'click', async () => {
    try {
      output.textContent = JSON.stringify(await sdk.rpc('run'), null, 2)
    } catch (error) {
      output.textContent = error.message
    }
  })
}
```

- `ctx` 是浏览器里的 Cordis 插件上下文。
- `sdk.el(tag, props, text)` 创建元素；text 使用 textContent。
- `sdk.mount(slot, element)` 挂载并自动登记卸载。
- `sdk.listen(target, event, handler)` 登记监听器并自动移除。
- `sdk.effect(() => cleanup)` 登记资源清理，或直接使用 `ctx.effect`。
- `sdk.rpc(method, args)` 调用本插件后端，默认 20 秒超时。
- `sdk.request(path, method, data)` 请求宿主 JSON API，插件卸载时取消未完成请求。
- `sdk.toast(message)` 显示反馈。
- `sdk.button(slot, label, handler)` 注册按钮并捕获异步点击错误。
- `sdk.provide(name, methods)` 注册 Cordis 服务；`sdk.service(name)` 获取服务，调用方需声明服务注入。
- `sdk.watch(service, handler)` 订阅实现 change 事件协议的服务，卸载时取消订阅。
- `sdk.guard(asyncFn)` 在本页管理操作停用功能前运行保存等检查；抛错阻止操作。
- 入口可返回清理函数，也可以返回 Promise<清理函数>。
- `sdk.signal` 在本次前端激活启动超时或卸载时取消；异步任务应主动遵守该信号。启动超时后才返回的清理函数仍会被立即执行，清理错误会记录到控制台；不会把已失败的实例重新标记为运行中。宿主不能强制终止任意 JavaScript 或撤销其外部副作用，资源创建后仍应尽早通过 `ctx.effect` 登记清理。

布局插件提供的插槽：`sidebar`、`toolbar`、`status`、`editor`、`footer`、`panels`。使用这些插槽应声明 `layout` 依赖。`list-filters` 由 `note-list` 提供。`app` 属于管理内核，可用于注册新的布局。

需要读取当前选中笔记时，声明 manifest 的 `notebook` 依赖，并在 client.js 添加：

```js
export const inject = ['notebook']
// 在入口中使用 ctx.notebook.current()、edit(patch)、flush()、create() 等。
```

UI 组件应通过公开服务与插槽协作，不直接查找其他插件的内部 DOM。前端当前为完全信任同页面执行，不隔离恶意代码。

## 3. 后端入口

```js
import { writeFile, readFile } from 'node:fs/promises'
import { join } from 'node:path'

export default function (ctx, api) {
  api.handle('run', async () => {
    const path = join(api.dataDir, 'result.txt')
    await writeFile(path, '来自插件的内容', 'utf8')
    const text = await readFile(path, 'utf8')
    const command = await api.exec(process.execPath, ['--version'])
    return { text, command }
  })
  ctx.effect(() => () => console.log('清理完成'))
}
```

- 每个启用的第三方后端在独立 Node 进程运行，内部使用 Cordis Context。
- `api.dataDir` 是插件专属数据目录的绝对路径。卸载代码不会删除它。
- `api.handle(name, fn)` 注册前端可调用的 JSON RPC 方法。参数与返回值应可序列化。
- `api.exec(command, args, options)` 返回 `{ code, stdout, stderr }`；默认 15 秒、最多 60 秒，输出最大 1 MB。非零退出码由调用方判断。
- `api.spawn(command, args, options)` 返回 Node ChildProcess，并登记进程，停用时清理。建议使用 SDK 启动命令，不自行创建脱离跟踪的后台进程。
- `api.host(method, args)` 调用宿主笔记服务。必须在 manifest dependencies 中显式声明 `notes`。
- `notes.list`、`notes.create` 无参数；`notes.update` 参数 `{ id, patch }`；`notes.remove` 参数 `{ id }`。
- 后端入口可以返回清理函数；定时器、连接等需通过 ctx.effect 清理。
- 启动超过 10 秒会失败。停用先请求正常清理，2 秒后仍未退出则终止进程树。Windows 使用 taskkill /T；SDK 登记子进程另行清理。

独立进程不等于安全沙箱。第一版允许后端直接使用 Node 文件、网络与命令模块；这些行为具有当前系统账户权限。插件停用不撤销已经产生的外部效果。

## 4. 打包与安装

在笔记本项目目录运行：

```sh
node scripts/pack-plugin.js path/to/my-plugin outputs/my-plugin.cordis-plugin.json
```

打包器生成 `{ manifest, files }` JSON，其中 files 是相对文件名到 UTF-8 源码的映射。允许 js、css、json、txt、html、svg；不允许符号链接、路径逃逸、package.json 或 plugin.json 覆盖。最多 100 个文件、2 MB 请求体。

当前不安装 npm 依赖。第三方包应先打包为自包含 ES 模块，Node 内置模块可以保留。不要直接上传包含 node_modules 的目录。

页面打开「插件管理」→ 选择本地包 → 确认完全信任 → 安装 → 启用。安装本身不会执行代码。查看运行状态和后端日志；失败后可重新启动，前端失败可重载前端。

## 5. 卸载和更新

先停用依赖该插件的功能，再停用插件。卸载只删除代码，保留 `data/plugin-data/<id>`。如需删除专属数据，在停用状态点击「清理数据」并输入插件 ID。

第一版不覆盖安装。更新需要停用、卸载旧版本、安装新版；数据目录保留。插件作者自行维护数据格式兼容性，当前没有自动迁移回滚。

## 6. 自带示例与验收

`examples/local-lab` 是完整示例，输出包为 `outputs/local-lab.cordis-plugin.json`。它不依赖笔记本源码内部接口，可通过安装流程独立添加前后端能力。

建议检查：反复启停后不重复出现组件或监听器；停用后没有 SDK 登记的后台进程；后端报错时主程序与管理页可用；修改数据后重新启用仍可读取；依赖缺失时提示明确。
