# Vite 开发与热更新

开发模式由 Vite 提供页面、前端源码转换、npm 依赖预构建、Tailwind 与 CSS 更新；Cordis 继续负责插件、服务依赖和资源生命周期。正式运行仍使用各插件自己声明的 dist 产物。插件的 package.json.cordis 协议、ID、配置和用户数据格式保持一致。

## 启动

```sh
pnpm install --frozen-lockfile
pnpm dev
```

打开 http://127.0.0.1:3210/ 。无需预先运行完整前端构建。开发启动会校验应用和插件清单，编译全部应用的后端；前端按当前应用的启用状态加载，不执行未打开应用的业务插件。

Vite 占用对外端口，Node 后端使用动态本机端口；API、SSE 和图片请求经同源代理转发。后端重启时 Vite 与热更新连接继续运行。`PORT`、`DATA_DIR`、`APPLICATIONS_DIR`、`APP` 与正式运行含义一致；开发入口面向包含源码和 build 声明的应用目录，导出运行包使用 `pnpm start:runtime`。

用独立数据验收时，在 PowerShell 中执行：

```powershell
$env:PORT = '3220'
$env:DATA_DIR = Join-Path (Get-Location) 'work/vite-data'
pnpm dev
```

关闭时按 Ctrl+C，会释放 Vite 和后端。数据路径与端口互相独立，不要让多个进程同时写相同数据目录。

## 修改后的行为

| 改动 | 更新方式 |
| --- | --- |
| 前端插件 JS/TS/JSX/TSX 或本插件相对导入 | Vite 编译预检，页面保存，Cordis 重建受影响插件；服务消费者随提供者释放和恢复，无关插件继续运行 |
| 声明的 CSS、Tailwind 入口及样式依赖 | Vite 更新已加载样式，无需整页刷新 |
| 常驻浏览器宿主、public/index.html | 页面保存后整页刷新 |
| 后端入口及其相对依赖、server/、shared/ | 编译后端，等待已就绪页面保存，重启 Node 后端，再刷新页面 |
| 应用或插件 package.json | 重新发现清单并编译，保存后重启后端及页面 |
| 已声明的静态资源 | 提供源码文件；浏览器缓存或持有资源的插件可能需要刷新/重载才能显示新内容 |
| 依赖安装、pnpm-lock.yaml、scripts/ | 重新运行开发命令，重建依赖预构建和工具实例 |
| 用户数据、dist、work、.workbench | 忽略，不触发开发重载 |

新插件仍只需要自己的清单和实现。新增 npm 依赖或 workspace 包后先 `pnpm install`，再重新运行 `pnpm dev`。类型变更使用 `pnpm typecheck` 验证；Vite 转换 TS 不代替类型检查。

## 为什么重载经过 Cordis

Vite 通知宿主哪些应用和插件的源码已变化，宿主按当前应用选择目标。它先执行原有 `plugins/before-stop` 保存保护，再释放对应 Fiber、导入新模块、重新激活。服务提供者被释放时，Cordis 自动处理消费者等待与恢复；节点、订阅、定时器等仍由所属上下文清理。React 继续只由 UI 服务提供一份。

这里使用插件生命周期重载，没有接入 React Fast Refresh。React 组件的局部状态和插件未持久化状态可能重置；笔记内容、当前笔记和画布偏好由既有保存、草稿及存储协议恢复。开发重载不能替代插件登记清理资源，也不能自动恢复所有外部副作用。

## 保存与失败恢复

后端更新采用“编译 → 页面保存确认 → 发布后端产物 → 关闭旧服务 → 启动新服务 → 页面刷新”。后端源码先编译到内存，全部编译成功后才准备重启，防止半套产物覆盖旧版本。

已就绪的开发页面会接到保存准备事件。宿主通过原有停止保护调用业务保存，并保持编辑保护直到后端重启结束。任一页面明确报告保存失败，都取消本次重启；解决保存问题后，再保存源码重试。

如果有页面 15 秒内未确认，则暂缓更新并释放其他页面的编辑保护，旧后端和旧产物继续服务。页面提示及工作台的 `development.blocked.clients` 会列出未响应页面的应用名和页面标识；唤醒这些页面，或在保存草稿后关闭它们，系统会自动重新编译最新源码、向当前页面发起新的保存确认，无需再次保存源码。保存准备和解除保护都带有同一轮 token，迟到的旧确认不能放行下一轮更新。等待期间的新后端修改仍保留在待更新状态，不会被一次仅刷新宿主的请求丢弃。

超时不等于保存成功：只要仍有页面未确认，就不会跳过它直接重启。插件没有保证落盘的草稿不能假定安全。

- 前端语法/依赖解析错误：显示 Vite 错误，保留正在运行的插件；修正源码后重新编译并重载。运行时 apply 错误仍由插件管理器显示，不能保证所有运行时异常可自动回滚。
- 后端编译错误：保留旧后端、旧产物和当前页面。
- 页面保存失败：不发布新后端产物，也不关闭旧服务。
- 新后端启动失败：恢复旧插件产物并尝试启动旧版本。宿主源码自身的运行时故障可能仍需修正源码后重试，无法保证进程外副作用回滚。

同时打开的标签页共用后端，但保存保护只覆盖已完成宿主初始化并接入开发通道的页面，不是跨页面数据事务。

## 源码、资源与正式构建

开发页面从 `/__cordis/dev` 取得清单映射的前端源入口、样式和公开资源。浏览器只能访问这些文件及 Vite 解析出的浏览器依赖图；后端入口、server/、package.json、用户数据和未声明文件不会因目录存在而公开。开发 source map 用于源码调试。服务绑定 127.0.0.1，只接受本机同源访问，不是公开部署入口。

生产和开发继续使用已有导入规则：包依赖声明在 dependencies，运行时服务依赖声明在 requires，跨插件协作用 ctx；React/React DOM 由 UI 插件共享。这些边界用于维护工程结构，不是恶意插件沙箱。

```sh
pnpm build                 # Vite 前端、Tailwind；esbuild 后端
pnpm build drawing         # 指定应用，仍构建宿主入口
pnpm start                 # 完整构建后正式运行
pnpm start:runtime         # 使用已有产物，不构建
pnpm test                  # 类型检查、正式构建、运行时回归
```

浏览器宿主仍生成 `public/runtime.js`，各插件仍生成清单声明的 `dist/client.js`、CSS 和静态资源。正式 HTTP 仅提供 public 声明的 dist 文件，导出协议无需改动。不要手改生成文件。

`pnpm workbench` 默认用同一开发服务运行内嵌应用，Agent 修改源码后同样热更新；开发服务通过 IPC 把插件更新、样式更新、页面刷新和编译错误告诉工作台，Agent 用 `workspace_status` 读取结果，并在页面刷新后自动重新绑定。工作台自身的聊天页面和 Pi 进程不热更新，修改它们仍需重启工作台。`pnpm workbench:production` 保留正式构建模式。

工作台通过 `/__cordis/identity` 校验开发子进程的 PID 和本次启动标识，只有校验通过且业务 API 正常才显示「热更新」。端口上已有其他服务时，会报告端口冲突，不将其误认成开发服务。每个工作台使用 `node_modules/.vite/cordis-workbench-<工作台实际端口>-<应用端口>` 作为缓存，同一实例重启复用缓存，并行工作台及普通 `pnpm dev` 互不覆盖依赖预构建。此身份校验用于确认进程归属，不是恶意进程认证机制。

## 维护入口与验证

- `scripts/dev.js`：开发服务、代理、监听、源码白名单和后端保存后重启。
- `scripts/development-save-guard.js`、`client/host/development-save.js`：多页面保存确认、按轮次解除保护、超时提示和恢复重试。
- `scripts/vite-build.js`：前端构建、JSX 转换和清单导入边界。
- `scripts/plugin-builder.js`：插件通用构建，支持只编译并暂存后端。
- `client/host/runtime.js`：开发事件、保存保护与重载协调。
- `client/host/plugin-host.js`：按插件释放和重新激活。
- `test/vite-development.test.js`：动态端口与独立数据，验证源码公开范围、CSS 更新、编译恢复、保存保护，以及真实 WebSocket 上的超时、恢复、关闭页面后自动重试。
- `test/development-save.test.js`：旧轮次确认不能授权新重启，慢保存、失去响应页面和等待任务的释放。
- `test/workbench-development.test.js`：真实开发子进程、外部服务拒绝、Agent 取得实际状态、并行工作台缓存隔离和刷新重绑定。
- `test/lifecycle.test.js`：提供者重载时消费者恢复，无关插件不重启。

在真实浏览器里至少验证一次：编辑内容后修改前端显示代码，内容保留且显示更新；修改 CSS，样式更新；修改后端代码，当前编辑保存并在重启后恢复。正式构建后再检查应用切换、插件启停及导出运行包。
