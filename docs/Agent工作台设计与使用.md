# Agent 工作台设计与使用

工作台为现有应用增加独立聊天与代码 Agent。使用 MIT 开源的 Pi Coding Agent SDK，直接调用 DeepSeek Chat Completions API，不使用 Codex app-server，也不是一个 Cordis 业务插件。

## 启动

需要 Node.js 22.19+（Pi SDK 的最低版本）与 pnpm。

```sh
pnpm install --frozen-lockfile
pnpm workbench
```

打开 `http://127.0.0.1:3211/`，点击网页右下角 Agent。业务应用仍使用 `http://127.0.0.1:3210/`，嵌在工作台 iframe 内，保持原来的浏览器存储来源。`/chat` 提供独立聊天页；此页可进行代码操作，但没有内嵌应用页面，不能直接修改正在另一个页面编辑的内容。

`pnpm workbench` 默认以 Vite 开发模式运行业务应用：工作台启动 `scripts/dev.js`，Agent 保存源码后自动热更新，无需构建、重启或手动刷新。前端插件由 Cordis 重载受影响插件，CSS 直接更新；后端、清单和宿主修改会先保存页面，再自动重启后端并刷新内嵌页面，Agent 随后自动绑定新页面继续操作。`workspace_status` 会等待最近的修改处理完成，并在 `development.events` 返回本轮的 plugins/css/reload/error 结果，编译错误因此能直接交给 Agent 修复。连接状态末尾的「热更新」只在开发服务身份与本工作台启动的子进程一致、且应用在线时显示。行为细节见 [Vite 开发与热更新](Vite开发与热更新.md)。

保存超时会显示「热更新等待 N 个页面保存」，并在 `development.blocked.clients` 返回应用名和页面标识。这个等待状态独立于最近事件列表，不会因日志截断消失。页面恢复或关闭后会自动重新尝试保存和更新；Agent 应报告等待原因，不要声称修改已经生效，也不要用 `workspace_restart` 绕过未确认的保存。

发布前验收使用 `pnpm workbench:production`：先完整构建，应用运行 `server/server.js` 读取各插件 dist；修改后需要 `workspace_build` 和 `workspace_restart`。开发缓存按工作台实际监听端口和应用端口分目录，同一实例重启复用缓存；多个工作台以及普通 `pnpm dev` 可使用各自缓存，但仍需不同端口和数据目录。

第一次在聊天设置中填写 API 密钥。默认基础地址 `https://api.deepseek.com/v1`，模型 `deepseek-v4-pro`，推理强度 High。也接受粘贴完整 `/chat/completions` 地址，保存时规范化为基础地址。密钥只在工作台后端传给模型请求，不返回前端。环境变量 `DEEPSEEK_API_KEY` 可作为初始值，本地配置优先；不自动读取 .env。

默认目录 `.workbench/` 被 Git 忽略，含 `config.json`（明文密钥）、`conversations.json`（界面历史与执行时间线）、`attachments/`（原始图片与元数据）和 `pi/sessions/`（Pi 对话与工具结果，含发给模型的图片）。备份时按私有资料处理；不要提交或分享这些文件。完全信任模式下，文件工具和命令具有当前账户权限，提示词中的约定不是密钥隔离沙箱。

`pnpm workbench:runtime` 以正式模式启动且跳过构建。环境变量：`WORKBENCH_PORT` 默认 3211，`WORKBENCH_APP_PORT` 默认 3210，`WORKBENCH_APP_MODE` 可设为 development 或 runtime，`WORKBENCH_DATA_DIR` 指定工作台私有目录，`DATA_DIR` 指定业务数据目录。工作台使用本仓库的 applications；单目录 PLUGINS_DIR 开发入口不属于此启动方式。

开发模式下，如果应用端口已有外部服务（包括另一个 Vite 实例），工作台会报告端口占用，返回 `mode: external`、`managed: false`，不会杀死或接管它。停止原服务或修改 `WORKBENCH_APP_PORT` 后再启动。正式模式仍允许连接端口上已有的运行服务，但不能代替它重启。不要同时用两个业务进程写同一数据目录。

## 三个进程

```text
浏览器工作台（3211，聊天 + iframe）
  ├─ 工作台服务：会话、模型设置、SSE、页面工具转发、应用进程管理
  ├─ Pi 子进程：模型循环、上下文压缩、文件读写、PowerShell/bash
  └─ 业务子进程（3210）：开发模式为 Vite 开发服务及其 Cordis 后端；正式模式为 Cordis 宿主 + dist
```

业务进程退出后，聊天继续运行；Agent 可读取日志、修改代码、构建并恢复业务进程。重启业务不会丢失会话。Agent 进程异常退出时，工作台保留聊天，再发消息会重新创建 Agent。工作台服务关闭则其子进程关闭；这不是守护整个操作系统或浏览器渲染器的高可用方案。业务插件若让浏览器标签页卡死，应使用独立 `/chat` 页操作代码。

某个应用的 `package.json` 损坏或缺失时，工作台仍可启动。应用选择器以目录名保留该应用并标记「清单错误」，可继续在其会话中用代码工具修复；正常应用不受该清单错误影响。

普通消息流式显示，每轮有独立执行时间线：耗时、所用模型与推理强度、模型返回的思考文本、每一次工具调用和压缩事件。展开工具可查看参数、命令与输出；输出作为纯文本展示。正文支持 Markdown 标题、表格、列表、引用、链接和代码复制，不执行模型输出的 HTML。思考与工具执行分别展示，没有返回思考文本时不会编造过程。

每轮任务的中间说明、思考和工具调用默认收进「用时…」执行过程，最终答复独立展示；更早各轮的最终答复仍然可见。执行时显示当前消息与活动状态，失败或停止会明确提示，不把中间说明当成成功答复。点击耗时可展开过程，工具本身还可单独展开；更新内容不会重建已有工具卡片或收起用户打开的过程。当前对话在同一标签页刷新后恢复，断线重连后从后端快照恢复时间线；刷新后过程默认收起。旧记录根据最后一条完整回复恢复展示。界面单项文字最多保留 256,000 字符，工具参数/输出最多 64,000 字符；完整模型/工具历史以 Pi 会话文件为准。流式记录约每 200 ms 合并保存，突然断电可能丢失最后尚未落盘的一小段；重启后未完成步骤会标为已停止。

模型因单次输出长度限制结束时，保留已经生成的回复并提示内容可能不完整，可发送「继续」获取后续内容；该提示随会话保存，刷新或重启后仍可见。若模型随后自动重试成功，则展示重试后的最终答复。

输入卡片将选区、图片预览、可自动增高的正文与操作栏放在一起，模型和推理强度位于底部，发送与停止使用同一位置。上下文用量位于卡片下方，权限和键盘说明可从信息按钮展开。向上阅读时不强行跟随输出，可用「回到最新」返回底部。面板、消息和过程展开使用轻量动效，并尊重系统的减少动态效果设置；窄窗口会调整布局。

可停止任务。停止不会撤销已经完成的文件或应用修改。Pi 的会话日志支持继续对话；中途异常不能保证副作用回滚，重试写操作前先检查结果。

模型临时错误和重试过程会保留在时间线中；后续重试成功则整轮显示「完成」，重试耗尽或发生最终错误才显示「失败」，用户中断显示「已停止」。

## 模型、推理强度和图片

以下能力来自 2026-09-27 核对的 [DeepSeek 模型接口](https://api-docs.deepseek.com/api/list-models/)、[思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/) 和 [视觉文档](https://api-docs.deepseek.com/guides/vision/)，集中声明在 `workbench/config.js`。

| 选项 | API 模型 ID | 输入能力 |
| --- | --- | --- |
| DeepSeek V4 Pro | `deepseek-v4-pro` | 文字 |
| DeepSeek V4.1 Flash | `deepseek-flash` | 文字、图片 |

两者均可选 Low / High / Max，也可关闭思考。输入框下的选择作用于下一次任务；设置页保存启动时的默认值。Pi 使用 `thinkingLevelMap` 显式声明档位，发送 DeepSeek 的 `thinking` 与 `reasoning_effort`，避免 SDK 把 Max 降回 High。模型真实窗口为 1,048,576 tokens，本工作台单次输出预算为 16,384 tokens。

输入框支持多选文件、拖入和粘贴多张图片，发送前有缩略图和删除按钮。粘贴读取浏览器实际提供的全部图片项；如果来源只把一张图片放到系统剪贴板，则无法推断其余图片，可以改用文件多选。文字与图片可以一并发送，也允许只发图片。

应用限制：每条最多 10 张，单张 8 MB，合计 20 MB；支持 PNG、JPEG、WebP、GIF，最长边 8192 像素，最多 4000 万像素。后端解码校验实际文件格式，不信任文件扩展名；图片不经过业务应用，不嵌入 UI 历史 JSON。历史图片仍可点击查看，删除待发送附件不会删除历史引用。

Pro 遇到当前附件或图片会话时会阻止发送，并提供明确的「切换 Flash 并发送」按钮；不会暗中换模型或丢弃图片。含图片的对话继续使用 Flash，纯文字 Pro 任务可另开对话。发送前还会检查已有上下文及图片的大小，接近请求体限制时提示压缩或新建对话。当前不会自动截取业务画布，也没有图像生成功能。

## 上下文压缩

设置可调整自动压缩开关、触发阈值（默认 **128,000 tokens**）与保留近期上下文（默认 **20,000 tokens**）。输入框下方显示当前估算用量及触发阈值，悬停可看真实模型窗口；「压缩」在空闲、有 Pi 历史的会话中可用。压缩也占用当前唯一任务槽，可停止，并在时间线显示开始、完成或失败。

复用 Pi 的自动/手动 compaction。内部把 `reserveTokens` 设置为真实窗口减去用户阈值，保留 SDK 在轮次边界的检查；摘要输出仍由模型单次输出预算限制。阈值不是严格的输入长度上限，单条很长的输入或不可分割的近期轮次可能暂时超出。阈值须至少为保留量 + 32768，且不超过模型窗口 - 16384。摘要可能丢失细节，原始界面记录和 Pi 原始会话条目保留；压缩后的精确用量等待下一轮接口回报。

## 两层上下文与应用绑定

每次任务读取 `agent/ARCHITECTURE.md` 和 `applications/<app>/agent.md`，因此业务应用离线时仍可理解架构。会话有固定 appId，页面工具进一步绑定工作台标签页、业务页面 pageId 和后端 session。

搜索统一通过 `exec_command` 执行 `rg`（内容）或 `rg --files`（路径），先限定相关源码范围；默认工具集不再暴露 Pi 的 `grep/find/ls/powershell/bash`。文件读取、编辑和写入仍用 `read/edit/write`。工作台把随依赖安装的 ripgrep 和项目 `node_modules/.bin` 加入命令 PATH；Windows 使用 PowerShell，其他平台使用 Bash。这是模型行为指导，不按命令名称封禁搜索。文档每轮重新读取；命令工具代码更新需重启工作台。

### 持续运行的命令

`yield_time_ms` 允许省略。`exec_command` 和 `workspace_build` 默认等待最多 10 秒；Windows 首次执行的有效窗口为 10–30 秒，较小值按 10 秒处理，其他平台保留 0–30 秒范围。`write_stdin` 无非空 `chars` 时属于纯轮询（含 `chars: ""`），默认 5 秒，有效范围 5–300 秒；发送非空输入时默认 250 毫秒，上限 30 秒。本项目的管道 EOF（`close_stdin: true`）也使用输入交互窗口。运行时将非负整数调整到对应有效范围。

这些都是单次等待窗口，不是固定调用间隔或执行超时；界面可以实时显示新输出，但普通输出不会提前结束模型侧的等待。进程退出、输入错误或取消可以提前结束等待；窗口到期只返回当前状态，命令继续运行。返回 `running` 与 `session_id` 后用 `write_stdin` 继续获取增量输出或输入文本。只有获得退出状态和退出码才能判断测试或构建结果，不能因为工具已返回就宣称成功。不会自动轮询或自动延长窗口，也不要求模型使用额外的 30–60 秒等待策略。

命令由工作台持有，跨 Agent 回复及浏览器刷新保留，并独立显示运行卡片、退出码和停止按钮。聊天“停止”终止本轮普通命令及子进程；仅启动时明确 `background=true` 的长期服务保留，用卡片或 `terminate_command` 单独停止。正常关闭工作台会清理全部受管理命令。重启后旧会话标为已中断，不重放命令或声称恢复；强杀工作台/系统崩溃不保证清理系统残留进程。

每个命令内存保留最近 256 Ki 字符，每次工具读取最多 16,000 字符；溢出返回 `dropped_chars`，未读完返回 `has_more`。界面只展示最近 12,000 字符。最近 40 个已完成命令保留在管理器，聊天保留最近 40 个已完成卡片，同时最多运行 16 个命令。日志不无限落盘，Pi 历史只包含实际读回给模型的片段。日志持续增长时应限定命令自身输出。浏览器展示不消耗 Agent 的读取位置。

普通命令使用管道，`close_stdin=true` 可发送 EOF。需要真实终端交互时指定 `tty=true`（node-pty；Windows ConPTY），随后通过 `write_stdin` 输入。PTY 不支持 `close_stdin`，退出使用程序自己的指令或明确终止工具。每个命令单独指定工作目录，不继承上一个命令的 `cd`。

管道输入接受后按顺序排队，EOF 在此前的输入写完后发送；写入阻塞也不会延长本次等待窗口。`stdin_pending_bytes` 表示尚未完成管道写入的字节数，写完不代表程序已处理；`stdin_error` 报告异步写入失败。待写入输入最多 256 KiB，达到上限时拒绝本次新增输入。已接受的输入不要重复发送，后续用不带 `chars` 的调用轮询。Windows 命令保留进程级 `ExecutionPolicy Bypass`；过长的命令通过临时 UTF-8 脚本执行，退出、停止或启动失败后清理，不修改系统执行策略。

切换应用会打开对应应用的新对话；旧对话可从所属应用的历史中找回。已经运行的任务继续绑定原应用，其代码工具仍可用，页面工具在应用/页面变更后拒绝执行。仅经工作台主动重启的任务可重新连接同一应用的新页面；旧选区不会跨刷新恢复。

同一工作台一次执行一个任务，各应用分别保存历史。任务期间可以继续手动编辑，应用写工具用 revision/version 或选区原文快照检测变化。检测到冲突时返回错误，不强制覆盖。

发送请求尚未返回时，可以切换应用、切换对话或继续输入。迟到的响应只更新原会话的历史，不抢回当前对话或清空新草稿；同一对话中后来添加的文字与图片也会保留。

## 工具边界

Pi 提供文件读取、编辑、写入和模型循环。工作台提供：

| 工具 | 用途 |
| --- | --- |
| exec_command | 启动普通命令或明确的后台服务，返回命令会话 |
| write_stdin | 读取增量输出或向命令输入文本 |
| list_commands | 查询当前聊天的命令状态，不能访问另一聊天的会话 |
| terminate_command | 终止指定命令及其子进程 |
| workspace_status | 应用连接、当前应用与最近日志 |
| workspace_build | 构建任务所属应用和通用浏览器入口，返回同样的命令会话；构建完成前保持互斥 |
| workspace_restart | 保存并锁住绑定页面，重启工作台管理的应用，再刷新页面 |
| app_list_tools | 发现当前页面已启用插件注册的工具 |
| app_call | 转发一个应用工具调用 |

第一版是直接注入 Pi 的工具桥接，**没有发布独立的标准 MCP 服务端**。应用接口采用 JSON Schema 描述，后续可加 MCP 适配器，不需要将笔记逻辑搬进工作台。

应用工具通过浏览器执行，能看到当前未保存状态；页面关闭、未连接或插件停用时，相应工具不可用。离线代码修复不依赖这些工具。

笔记工具由 notebook/agent-tools 插件提供，支持列表、读取、打开、新建与带 revision 的修改；画图工具由 drawing/canvas 注册，支持读取与带 version 的画作修改。业务验证、保存和撤销由业务代码处理。当前不提供自动删除笔记工具、网络搜索或插件市场。

## 添加选区

在普通笔记、Markdown 源码区或自由页面富文本中选择文字，右键「添加到 Chat」。聊天附件保存引用文字及随机定位 ID，Agent 可调用 `replace_selection`。

应用侧保留真正的选区位置与原文快照；Agent 提供替换内容，由原编辑器执行，支持原生/自由页面历史撤销。用户改变原文、切换笔记、停用插件或刷新页面后，旧定位失效。当前一次消息最多 10 个选区；整篇 notebook_update 与局部选区替换的撤销语义不同，局部修改优先后者。

普通笔记和 Markdown 源码选区使用 `{id,text}`，保持纯文字语义。自由页面附件额外提供 `formats: ["text", "richtext"]`、选区结构 `richText` 及 `replacementHint`。对这类选区，可调用 `app_call`：

```json
{
  "name": "replace_selection",
  "arguments": {
    "id": "附件中的定位 ID",
    "format": "richtext",
    "content": {
      "version": 1,
      "elements": [{ "kind": "paragraph", "runs": [{ "text": "强调的文字", "format": { "bold": true, "color": "#b13d65" } }] }]
    }
  }
}
```

片段采用 rich-text 插件的 OutlineDocument，支持字形、颜色、标题、列表、表格及已有本地图片等原编辑器能力。单个普通段落的行内格式保留在原段落中，结构性片段按编辑器事务插入；只修改选区。缺省格式为 `text`，不能同时传 `text` 与 `content`。宿主只负责能力转发，结构校验、内容上限、保存和撤销由插件处理，不解析任意 HTML。成功后定位 ID 失效；失败时需根据错误重新读取或添加选区。

富文本替换使用片段自身的文字格式：无格式的文字片段会清除选区原有的加粗、颜色、链接等标记，同时保留选区前后文字的格式。纯文本替换仍沿用原编辑器继承样式的行为。

## 给新应用接入

1. 增加应用自己的 `agent.md`，说明服务、数据类型、工具、修改与验证方式。
2. 在应用插件中调用 `sdk.agent.register({ name, description, inputSchema }, execute)`。注册跟随插件生命周期，卸载时自动移除。name 使用小写字母、数字和下划线；执行函数负责业务校验、冲突检测和持久化。
3. 编辑器可调用 `sdk.agent.selection(element, capture)`。capture 返回 `{text,label,apply(text)}`，需要时附加 noteId/blockId。支持格式化替换的插件还声明 `formats`、`richText`、`replacementHint` 与 `applyContent({format,content})`。apply/applyContent 自行校验原文并使用编辑器事务修改，不能绕过撤销或保存。
4. 新应用不需要更改工作台工具清单或添加宿主业务分支。清单扫描后，需要重启工作台才能发现新增应用目录。

工作台与业务页面只信任各自的本机来源，并校验消息 source、origin 和页面/session。写 HTTP 接口要求同源 JSON，图片上传使用独立的同源二进制接口；只监听 127.0.0.1。此版本不适合公网部署，也没有多用户登录、权限审批或命令沙箱。

## 修改和验证

开发模式下修改业务插件只需保存并运行相关测试；正式模式下构建对应应用，后端或清单修改后重启。依赖或 `scripts/` 变更需要用 `workspace_restart` 重启开发服务。工作台代码变更需要重启工作台自身。`pnpm build` 同时生成工作台 Markdown 浏览器模块；仅修改工作台时可执行 `node workbench/build.js`。`pnpm test` 包含工作台协议、选区桥接和现有应用回归；新增测试使用真实 Pi SDK + 模拟模型端点验证三档强度、多图和压缩请求，并测试 Markdown 与稳定 DOM 更新。真实 API 验证会产生模型费用，不把密钥放入测试夹具。
