# Agent 工作台设计与使用

工作台为现有应用增加独立聊天与代码 Agent。使用 MIT 开源的 Pi Coding Agent SDK，直接调用 DeepSeek Chat Completions API，不使用 Codex app-server，也不是一个 Cordis 业务插件。

## 启动

需要 Node.js 22.19+（Pi SDK 的最低版本）与 pnpm。

```sh
pnpm install --frozen-lockfile
pnpm workbench
```

打开 `http://127.0.0.1:3211/`，点击网页右下角 Agent。业务应用仍使用 `http://127.0.0.1:3210/`，嵌在工作台 iframe 内，保持原来的浏览器存储来源。`/chat` 提供独立聊天页；此页可进行代码操作，但没有内嵌应用页面，不能直接修改正在另一个页面编辑的内容。

第一次在聊天设置中填写 API 密钥。默认基础地址 `https://api.deepseek.com/v1`，模型 `deepseek-v4-pro`，推理强度 High。也接受粘贴完整 `/chat/completions` 地址，保存时规范化为基础地址。密钥只在工作台后端传给模型请求，不返回前端。环境变量 `DEEPSEEK_API_KEY` 可作为初始值，本地配置优先；不自动读取 .env。

默认目录 `.workbench/` 被 Git 忽略，含 `config.json`（明文密钥）、`conversations.json`（界面历史与执行时间线）、`attachments/`（原始图片与元数据）和 `pi/sessions/`（Pi 对话与工具结果，含发给模型的图片）。备份时按私有资料处理；不要提交或分享这些文件。完全信任模式下，文件工具和命令具有当前账户权限，提示词中的约定不是密钥隔离沙箱。

`pnpm workbench:runtime` 跳过构建。环境变量：`WORKBENCH_PORT` 默认 3211，`WORKBENCH_APP_PORT` 默认 3210，`WORKBENCH_DATA_DIR` 指定工作台私有目录，`DATA_DIR` 指定业务数据目录。工作台使用本仓库的 applications；单目录 PLUGINS_DIR 开发入口不属于此启动方式。

如果 3210 已有服务，工作台可连接它，但不会杀死或接管它。要使用受管理的重启，请先停止原服务，再启动工作台。不要同时用两个业务进程写同一数据目录。

## 三个进程

```text
浏览器工作台（3211，聊天 + iframe）
  ├─ 工作台服务：会话、模型设置、SSE、页面工具转发、应用进程管理
  ├─ Pi 子进程：模型循环、上下文压缩、文件读写、PowerShell/bash
  └─ 业务子进程（3210）：Cordis 宿主 + 当前应用插件
```

业务进程退出后，聊天继续运行；Agent 可读取日志、修改代码、构建并恢复业务进程。重启业务不会丢失会话。Agent 进程异常退出时，工作台保留聊天，再发消息会重新创建 Agent。工作台服务关闭则其子进程关闭；这不是守护整个操作系统或浏览器渲染器的高可用方案。业务插件若让浏览器标签页卡死，应使用独立 `/chat` 页操作代码。

某个应用的 `package.json` 损坏或缺失时，工作台仍可启动。应用选择器以目录名保留该应用并标记「清单错误」，可继续在其会话中用代码工具修复；正常应用不受该清单错误影响。

普通消息流式显示，每轮有独立执行时间线：耗时、所用模型与推理强度、模型返回的思考文本、每一次工具调用和压缩事件。展开工具可查看参数、命令与输出；输出作为纯文本展示。正文支持 Markdown 标题、表格、列表、引用、链接和代码复制，不执行模型输出的 HTML。思考与工具执行分别展示，没有返回思考文本时不会编造过程。

工具结果默认折叠，执行中的项目突出显示；更新内容不会重建已有工具卡片。当前对话在同一标签页刷新后恢复，断线重连后从后端快照恢复时间线。界面单项文字最多保留 256,000 字符，工具参数/输出最多 64,000 字符；完整模型/工具历史以 Pi 会话文件为准。流式记录约每 200 ms 合并保存，突然断电可能丢失最后尚未落盘的一小段；重启后未完成步骤会标为已停止。

可停止任务。停止不会撤销已经完成的文件或应用修改。Pi 的会话日志支持继续对话；中途异常不能保证副作用回滚，重试写操作前先检查结果。

模型临时错误和重试过程会保留在时间线中；后续重试成功则整轮显示「完成」，重试耗尽或发生最终错误才显示「失败」，用户中断显示「已停止」。

## 模型、推理强度和图片

以下能力来自 2026-09-27 核对的 [DeepSeek 模型接口](https://api-docs.deepseek.com/api/list-models/)、[思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/) 和 [视觉文档](https://api-docs.deepseek.com/guides/vision/)，集中声明在 `workbench/config.js`。

| 选项 | API 模型 ID | 输入能力 |
| --- | --- | --- |
| DeepSeek V4 Pro | `deepseek-v4-pro` | 文字 |
| DeepSeek V4.1 Flash | `deepseek-flash` | 文字、图片 |

两者均可选 Low / High / Max，也可关闭思考。输入框下的选择作用于下一次任务；设置页保存启动时的默认值。Pi 使用 `thinkingLevelMap` 显式声明档位，发送 DeepSeek 的 `thinking` 与 `reasoning_effort`，避免 SDK 把 Max 降回 High。模型真实窗口为 1,048,576 tokens，本工作台单次输出预算为 16,384 tokens。

输入框支持多选文件、拖入和粘贴多张图片，发送前有缩略图和删除按钮。粘贴读取浏览器实际提供的全部图片项；如果来源只把一张图片放到系统剪贴板，则无法推断其余图片，可以改用文件多选。文字与图片可以一并发送，也允许只发图片。

应用限制：每条最多 10 张，单张 8 MB，合计 20 MB；支持 PNG、JPEG、WebP、GIF，最长边 8192 像素，最多 4000 万像素。后端解码校验实际文件格式，不信任文件扩展名；图片不经过业务应用，不嵌入 UI 历史 JSON。历史图片仍可点击查看，删除待发送附件不会删除历史引用。

Pro 遇到当前附件或图片会话时会阻止发送，并提供明确的「切换 Flash 并发送」按钮；不会暗中换模型或丢弃图片。含图片的对话继续使用 Flash，纯文字 Pro 任务可另开对话。发送前还会检查已有上下文及图片的大小，接近请求体限制时提示压缩或新建对话。当前不会自动截取业务画布，也没有图像生成功能。

## 上下文压缩

设置可调整自动压缩开关、触发阈值（默认 **128,000 tokens**）与保留近期上下文（默认 **20,000 tokens**）。输入框上方显示当前估算用量及触发阈值，悬停可看真实模型窗口；「立即压缩」在空闲、有 Pi 历史的会话中可用。压缩也占用当前唯一任务槽，可停止，并在时间线显示开始、完成或失败。

复用 Pi 的自动/手动 compaction。内部把 `reserveTokens` 设置为真实窗口减去用户阈值，保留 SDK 在轮次边界的检查；摘要输出仍由模型单次输出预算限制。阈值不是严格的输入长度上限，单条很长的输入或不可分割的近期轮次可能暂时超出。阈值须至少为保留量 + 32768，且不超过模型窗口 - 16384。摘要可能丢失细节，原始界面记录和 Pi 原始会话条目保留；压缩后的精确用量等待下一轮接口回报。

## 两层上下文与应用绑定

每次任务读取 `agent/ARCHITECTURE.md` 和 `applications/<app>/agent.md`，因此业务应用离线时仍可理解架构。会话有固定 appId，页面工具进一步绑定工作台标签页、业务页面 pageId 和后端 session。

通用上下文中的搜索约定要求 Agent 默认使用 `grep` 搜索内容、`find` 查找文件、`ls` 查看目录，并先限定相关源码范围；仅在这些工具不能满足需求时退回命令行。PowerShell 保留构建、测试等能力。这是模型行为指导，不是强制拦截；修改这些上下文文档后，下一次任务会重新读取，已有会话也适用，无需重启工作台。

切换应用会打开对应应用的新对话；旧对话可从所属应用的历史中找回。已经运行的任务继续绑定原应用，其代码工具仍可用，页面工具在应用/页面变更后拒绝执行。仅经工作台主动重启的任务可重新连接同一应用的新页面；旧选区不会跨刷新恢复。

同一工作台一次执行一个任务，各应用分别保存历史。任务期间可以继续手动编辑，应用写工具用 revision/version 或选区原文快照检测变化。检测到冲突时返回错误，不强制覆盖。

发送请求尚未返回时，可以切换应用、切换对话或继续输入。迟到的响应只更新原会话的历史，不抢回当前对话或清空新草稿；同一对话中后来添加的文字与图片也会保留。

## 工具边界

Pi 提供文件读取、搜索、编辑、写入和命令。工作台提供：

| 工具 | 用途 |
| --- | --- |
| workspace_status | 应用连接、当前应用与最近日志 |
| workspace_build | 构建任务所属应用和通用浏览器入口 |
| workspace_restart | 保存并锁住绑定页面，重启工作台管理的应用，再刷新页面 |
| app_list_tools | 发现当前页面已启用插件注册的工具 |
| app_call | 转发一个应用工具调用 |

第一版是直接注入 Pi 的工具桥接，**没有发布独立的标准 MCP 服务端**。应用接口采用 JSON Schema 描述，后续可加 MCP 适配器，不需要将笔记逻辑搬进工作台。

应用工具通过浏览器执行，能看到当前未保存状态；页面关闭、未连接或插件停用时，相应工具不可用。离线代码修复不依赖这些工具。

笔记工具由 notebook/agent-tools 插件提供，支持列表、读取、打开、新建与带 revision 的修改；画图工具由 drawing/canvas 注册，支持读取与带 version 的画作修改。业务验证、保存和撤销由业务代码处理。当前不提供自动删除笔记工具、网络搜索或插件市场。

## 添加选区

在普通笔记、Markdown 源码区或自由页面富文本中选择文字，右键「添加到 Chat」。聊天附件保存引用文字及随机定位 ID，Agent 可调用 `replace_selection`。

应用侧保留真正的选区位置与原文快照；Agent 提供替换文字，由原编辑器执行，支持原生/TipTap 撤销。用户改变原文、切换笔记、停用插件或刷新页面后，旧定位失效。替换插入纯文字，不解析任意 HTML。当前一次消息最多 10 个选区；整篇 notebook_update 与局部选区替换的撤销语义不同，局部修改优先后者。

## 给新应用接入

1. 增加应用自己的 `agent.md`，说明服务、数据类型、工具、修改与验证方式。
2. 在应用插件中调用 `sdk.agent.register({ name, description, inputSchema }, execute)`。注册跟随插件生命周期，卸载时自动移除。name 使用小写字母、数字和下划线；执行函数负责业务校验、冲突检测和持久化。
3. 编辑器可调用 `sdk.agent.selection(element, capture)`。capture 返回 `{text,label,apply(text)}`，需要时附加 noteId/blockId。apply 自行校验原文并使用编辑器事务修改，不能绕过撤销或保存。
4. 新应用不需要更改工作台工具清单或添加宿主业务分支。清单扫描后，需要重启工作台才能发现新增应用目录。

工作台与业务页面只信任各自的本机来源，并校验消息 source、origin 和页面/session。写 HTTP 接口要求同源 JSON，图片上传使用独立的同源二进制接口；只监听 127.0.0.1。此版本不适合公网部署，也没有多用户登录、权限审批或命令沙箱。

## 修改和验证

修改业务插件后构建对应应用、运行相关测试，后端或清单修改后重启。工作台代码变更需要重启工作台自身。`pnpm build` 同时生成工作台 Markdown 浏览器模块；仅修改工作台时可执行 `node workbench/build.js`。`pnpm test` 包含工作台协议、选区桥接和现有应用回归；新增测试使用真实 Pi SDK + 模拟模型端点验证三档强度、多图和压缩请求，并测试 Markdown 与稳定 DOM 更新。真实 API 验证会产生模型费用，不把密钥放入测试夹具。
