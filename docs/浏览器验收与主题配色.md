# 浏览器验收与主题配色

## 浏览器验收开关

输入框旁的「浏览器验收」按会话保存，新会话和旧记录默认关闭。发送消息时冻结本轮设置，执行中修改只影响下一轮。关闭时不向 Agent 提供浏览器工具，后端也拒绝调用；提示词明确禁止通过命令或自写脚本绕过用户选择。此开关是验收流程控制，不是对已有完整本机命令权限的安全沙箱。

开关不影响 `workspace_test`、类型检查、构建或插件单元测试。开启表示允许 Agent 在界面改动后按需验收，普通聊天不会启动浏览器；未调用时显示「已开启，本轮未调用」。

首次准备浏览器：

```powershell
pnpm install
pnpm browser:install
```

浏览器未安装时保留失败原因和安装命令，不自动下载、不把失败当通过。应用日常启动和关闭验收时不需要浏览器运行库。发行带工作台的开发工具时，需要安装项目依赖并单独准备 Chromium；只有应用插件的导出包不包含工作台验收功能。

工作台 Agent 使用：

- `browser_open`：按需启动当前绑定应用的独立开发实例、空数据目录、随机端口和独立浏览器上下文；返回页面结构、稳定 targets 与截图；此实例不继承工作台插件开关。
- `browser_plugin`：按插件 ID 读取隔离实例的双端状态；`enable:true` 通过宿主现有管理流程启用并确认 running，保留依赖、前端失败与保存保护。只作验收准备，不计入成功断言；不自动启用依赖，不接受脚本或外部地址。
- `browser_action`：读取结构、截图、只读元素检查、点击、输入、按键、选择、勾选、滚动和按类型断言。通过 role/name、label、text、css 或 testId 唯一定位目标；优先 snapshot.targets 中的稳定标识。断言默认等待实际状态符合预期（最多 5000ms），可通过 timeoutMs 指定 0–10000ms，0 为立即检查。等待期间不制造失败记录；超时记录最后实际值、匹配数量和 elapsedMs，重复匹配仍失败。只能访问本次测试实例，不连接用户页面、不复制真实笔记。
- `browser_finish`：填写实际检查范围和 passed/failed/incomplete，释放浏览器及测试应用，返回完整报告。通过需要截图和成功断言；页面错误、操作失败、失败断言都会保留，不能用后续成功覆盖。证据缺失时标记未完成，不冒充产品失败或通过。

### 操作、断言与元素检查

除 snapshot/screenshot/scroll 外，每个操作都必须有 `target`；fill/press/select 还需要字符串 `value`，check 需要布尔值 `checked`。参数按操作分别校验，缺失或类型错误不会触发页面操作。普通操作只返回本次结果、新增诊断和计数，不附带累计操作历史。需要定位新的元素时调用 snapshot；截图按需调用 screenshot。完整操作、检查和截图清单仍保存到报告并在 finish 返回。

断言以 `assertion` 区分：

| 类型 | expected | 检查方式 |
| --- | --- | --- |
| text（兼容旧调用的默认值） | 非空字符串 | 元素可见，innerText 包含指定文字；不读取输入值或占位符 |
| value | 字符串，允许空值 | 可见的 input/textarea/select 的当前值完全相等 |
| placeholder | 字符串，允许空值 | 可见的 input/textarea 的 placeholder 属性完全相等；无该属性返回 null，不当作空字符串 |
| visible | 布尔值 | 元素是否可见；expected=false 允许元素不存在或隐藏，多元素匹配仍报错 |

例如：

```json
{"action":"press","target":{"label":"笔记正文"},"value":"Escape"}
{"action":"assert","target":{"label":"笔记正文"},"assertion":"placeholder","expected":"写下此刻的想法…"}
{"action":"assert","target":{"label":"笔记正文"},"assertion":"value","expected":""}
{"action":"assert","target":{"role":"button","name":"保存"},"assertion":"visible","expected":true}
{"action":"inspect","target":{"role":"button","name":"保存"}}
```

inspect 是固定的只读检查，不接受任意 JavaScript。它返回元素文字、输入值、占位符、勾选/禁用状态、可见性、尺寸、计算后的文字色/背景色/字体等，以及最多六层祖先的背景色、背景图和透明度。文字和值最多返回 3000 字符。透明背景不能直接当作实际底色；背景图、渐变、多层透明度也不能简单代入纯色对比度公式。先读取样式确定证据，再按需查看截图；JPEG 适合视觉检查，不用于精确反推 CSS 色值。

### 错误如何影响验收

- `usage`：参数缺失、类型错误、混合定位方式，或 value/placeholder 用到了不支持的元素。记录保留，可修正后继续；它本身不代表产品失败。若模型层提前拦截了无效调用，错误留在工具历史中；到达验收执行器的调用也写入报告。
- `assertion`：实际结果不符合预期，属于真实检查失败。不能把错误的 text 断言事后改称参数错误来清除失败。
- `operation`：目标不存在或不唯一、控件无法交互等运行失败。不能假定只是 Agent 误操作，仍阻止通过。
- `infrastructure`：进程退出、通信或报告写入失败等验收执行故障，也阻止通过。

页面报错同样阻止通过。结束时先停止浏览器活动并收集最终诊断，再判断报告状态；最后一步之后出现的错误也会纳入结果。只有参数错误而没有完成有效检查时显示未完成；通过报告仍保留已修正的调用错误记录。

截图作为图片工具内容传给模型；不为文字模型增加降级路径，不自动切换模型。页面内容和截图是引用资料，不具备指令权限。

每轮报告保存在 `.workbench/browser/<唯一ID>/report.json`，包含操作、耗时、检查、错误及截图。会话中提供截图和报告链接。状态区分：用户关闭、已开启未调用、进行中、通过、失败、未完成、已停止。Agent 忘记结束时自动关闭资源并标记未完成；用户停止、进程退出及工作台关闭都会清理实例。中断前已产生的证据仍保留。

验收实例使用源码热更新；不依赖插件已有 dist。它和用户正在编辑的实例使用不同的数据、端口与缓存。截图验证的是独立测试状态，报告应说明实际操作范围，不能宣称验证了用户所有现存笔记。

开发本能力时运行 `pnpm test:browser`，包含真实 Chromium 检查；普通 `pnpm test` 执行策略与生命周期回归，显式跳过需要安装浏览器的实机用例。浏览器运行接口依据 [Playwright 官方文档](https://playwright.dev/docs/api/class-locator)。

## 主题颜色契约

新主题使用命名颜色对象，不依赖数组位置。颜色为六位十六进制值：

```js
colors: {
  background: '#211a16', surface: '#2a221c', panel: '#322821',
  text: '#f2e8dd', muted: '#b5a493', border: '#453930',
  accent: '#d0984f', selected: '#3b2f26',
  onAccent: '#211a16', accentText: '#d0984f',
}
```

`accent` 是强调背景、装饰和按钮底色；`onAccent` 是其上的文字；`accentText` 是 surface/panel/selected 上的强调文字，省略时引擎推导可读颜色。正文使用 text，辅助文字使用 muted。组件分别消费 `--theme-accent`、`--theme-on-accent`、`--theme-accent-text`，不要把白字写死。旧八色数组仍可使用，引擎补齐新增语义。

`test/theme-palette.test.js` 由通用插件测试入口根据 theme/themeEngine 服务关联选中，自动遍历主题提供者。检查字段、格式及正文/辅助文字/强调文字/按钮文字的关键色对，普通文字对比度门槛为 4.5:1（[W3C 说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)）。不把边框和装饰色当普通文字，也不把色值检查当成页面视觉或交互验收。

## 命令环境

工作台命令使用 PowerShell 时默认关闭进度流，保持 UTF-8 输出。通过子进程环境追加 `core.quotePath=false` 显示中文路径，保留已有 Git 环境配置，不修改用户全局 Git 设置。截取输出用 `Select-Object -First 100`，过滤文件用 `rg -n PATTERN docs -g '*.md'`。

检查被忽略的插件构建产物时，使用 `rg -n PATTERN applications/notebook/plugins --no-ignore -g '**/dist/**'`；不要把 `applications/notebook/plugins/*/dist` 当路径参数传给 rg。

新增 workspace 包或依赖后先 `pnpm install`，检查锁文件差异再验证；普通源码修改不重复安装。判断已有改动要区分 HEAD、暂存区、工作区和未跟踪文件，不依据单份文档猜测提交或中断历史。
