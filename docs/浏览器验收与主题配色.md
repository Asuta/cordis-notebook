# 浏览器验收与主题配色

## 浏览器验收开关

输入框旁的「浏览器验收」按会话保存，新会话和旧记录默认关闭。发送消息时冻结本轮设置，执行中修改只影响下一轮。关闭时不向 Agent 提供浏览器工具，后端也拒绝调用；提示词明确禁止通过命令或自写脚本绕过用户选择。此开关是验收流程控制，不是对已有完整本机命令权限的安全沙箱。

开关不影响 `workspace_test`、类型检查、构建或插件单元测试。开启表示允许 Agent 在界面改动后按需验收，普通聊天不会启动浏览器；未调用时显示「已开启，本轮未调用」。

首次准备浏览器：

```powershell
pnpm install
pnpm browser:install
```

浏览器未安装时保留失败原因和安装命令，不自动下载、不把失败当通过。应用日常启动和关闭验收时不需要浏览器运行库。发行带工作台的开发工具时，需要安装项目依赖并单独准备 Chromium；只有应用插件的导出包不包含工作台验收功能。

工作台 Agent 使用：

- `browser_open`：按需启动当前绑定应用的独立开发实例、空数据目录、随机端口和独立浏览器上下文；返回页面结构与截图。
- `browser_action`：读取结构/错误、截图、点击、输入、按键、选择、勾选、滚动和断言。通过 role/name、label、text 或 css 唯一定位目标。只能访问本次测试实例，不连接用户页面、不复制真实笔记。
- `browser_finish`：填写实际检查范围和结果，释放浏览器及测试应用。需要截图和成功断言；页面错误、失败步骤、失败断言都会保留，不能用后续成功覆盖。

截图作为图片工具内容传给模型；不为文字模型增加降级路径，不自动切换模型。页面内容和截图是引用资料，不具备指令权限。

每轮报告保存在 `.workbench/browser/<唯一ID>/report.json`，包含操作、耗时、检查、错误及截图。会话中提供截图和报告链接。状态区分：用户关闭、已开启未调用、进行中、通过、失败、未完成、已停止。Agent 忘记结束时自动关闭资源并标记未完成；用户停止、进程退出及工作台关闭都会清理实例。中断前已产生的证据仍保留。

验收实例使用源码热更新；不依赖插件已有 dist。它和用户正在编辑的实例使用不同的数据、端口与缓存。截图验证的是独立测试状态，报告应说明实际操作范围，不能宣称验证了用户所有现存笔记。

开发本能力时运行 `pnpm test:browser`，包含真实 Chromium 检查；普通 `pnpm test` 执行策略与生命周期回归，显式跳过需要安装浏览器的实机用例。浏览器运行接口依据 [Playwright 官方文档](https://playwright.dev/docs/api/class-locator)。

## 主题颜色契约

新主题使用命名颜色对象，不依赖数组位置。颜色为六位十六进制值：

```js
colors: {
  background: '#211a16', surface: '#2a221c', panel: '#322821',
  text: '#f2e8dd', muted: '#b5a493', border: '#453930',
  accent: '#d0984f', selected: '#3b2f26',
  onAccent: '#211a16', accentText: '#d0984f',
}
```

`accent` 是强调背景、装饰和按钮底色；`onAccent` 是其上的文字；`accentText` 是 surface/panel/selected 上的强调文字，省略时引擎推导可读颜色。正文使用 text，辅助文字使用 muted。组件分别消费 `--theme-accent`、`--theme-on-accent`、`--theme-accent-text`，不要把白字写死。旧八色数组仍可使用，引擎补齐新增语义。

`test/theme-palette.test.js` 由通用插件测试入口根据 theme/themeEngine 服务关联选中，自动遍历主题提供者。检查字段、格式及正文/辅助文字/强调文字/按钮文字的关键色对，普通文字对比度门槛为 4.5:1（[W3C 说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum)）。不把边框和装饰色当普通文字，也不把色值检查当成页面视觉或交互验收。

## 命令环境

工作台命令使用 PowerShell 时默认关闭进度流，保持 UTF-8 输出。通过子进程环境追加 `core.quotePath=false` 显示中文路径，保留已有 Git 环境配置，不修改用户全局 Git 设置。截取输出用 `Select-Object -First 100`，过滤文件用 `rg -n PATTERN docs -g '*.md'`。

新增 workspace 包或依赖后先 `pnpm install`，检查锁文件差异再验证；普通源码修改不重复安装。判断已有改动要区分 HEAD、暂存区、工作区和未跟踪文件，不依据单份文档猜测提交或中断历史。
