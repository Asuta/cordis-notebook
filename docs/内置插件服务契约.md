# 内置插件服务契约

初次接手请先读 [项目接手与维护指南](项目接手与维护指南.md)，了解启动方式、源码结构及完整开发流程；本文用于查阅具体接口。

适用于本项目的前端内置插件。各提供能力的插件在自己的 types/ 中声明服务与事件类型，宿主包 `@cordis-notebook/host` 提供 ClientContext、ServerContext 和通用协议，`test/contracts.types.ts` 检查正确调用和应当被拒绝的错误调用。现有 JavaScript 项目不要求整体迁移到 TypeScript。第三方 API v1 包格式、安装与后端进程协议保持原样。

类型按 data/client/server 入口引用，具体方法见 [Workspace 插件开发指南](Workspace插件开发指南.md)。

## 1. 服务负责业务与注册，插件负责自己的生命周期

所有业务能力由插件提供。插件只能直接导入自身目录中的实现或外部包；跨插件能力通过 `requires`/`inject` 声明并调用 ctx 服务。宿主公共代码不属于业务插件，也不供插件直接导入。

| 服务与提供插件 | 公开接口 | 生命周期 |
| --- | --- | --- |
| `markdown` / `markdown` | `render(source): string`、`toText(source): string` | 前后端各自创建解析实例；格式和编辑器显式依赖，服务缺失时等待，恢复后重新绑定 |
| `themeEngine` / `theme-engine` | 前端 `apply(owner, {id,name,colors,dark?})`，colors 为八色数组，返回释放函数；后端 `activate(owner, id)` | 样式与 theme 服务属于传入的主题 owner，主题或引擎卸载都会通过 Cordis 清理消费者资源 |
| `noteFormats` / `note-formats` | `typeOf(note)` 兼容旧笔记；`snapshot(value)` 返回深只读副本；其余注册接口见下文 | 公共工具属于格式服务，消费者不直接引用其内部 note.js |

后端 HTTP 宿主公开 `ctx.http.body(req)`，统一应用 JSON 解析与请求大小限制；notes-api 插件通过服务调用，不导入宿主文件。此接口不在浏览器 Context 上提供。

停止仍被使用的能力插件会被依赖保护阻止；先停用依赖方再停用提供者。异常失去解析服务时撤销 Markdown 格式并保留已有数据，恢复后重新注册。现有插件 ID 保留，新增 markdown、theme-engine 默认启用。第三方 API v1 的子进程服务注册/RPC 能力未在本次扩展。

`ctx.noteFormats` 在前后端分别提供格式注册能力。格式插件声明 `noteFormats` 依赖，通过 `register(ctx, definition)` 登记；通用笔记服务调用 `create/update/patch`，列表通过 `list()` 生成新建菜单。完整声明、生命周期及新增格式示例见 [笔记格式插件开发指南](笔记格式插件开发指南.md)。

编辑器通过 `ctx.editorHost.register(owner, editorId, node)` 注册 DOM 视图；格式声明的 `editor` 指向此 ID。视图与注册随 owner 清理，重复 ID 会报错。编辑区先查询 `noteFormats` 再选择编辑器；缺少格式或编辑器时显示不同提示，不改写笔记内容。`notebook.editable` 表示当前格式可用且没有待恢复草稿阻止编辑。

`notebook.create(type = 'plain')` 创建对应格式；`edit({blocks})` 更新自由页面。每个容器包含 `id/x/y/width/text`，富文本容器增加 `outline`；页面增加 `version: 2` 与 `page` 纸张设置。`richText` 提供文档规范化、纯文本提取及前端编辑器挂载，`noteAssets.upload(file)` 返回本地图片地址（单张最多 1 MiB）；接口与存储说明见 [自由页面设计与使用](自由页面设计与使用.md)。页面最多 1000 个容器，提取正文最多 200000 个 JS 字符。`current()` 与 `visible()` 返回的文字块也是冻结副本。自由页面的 `content` 按 y、x 顺序从 blocks 派生，供现有搜索、统计、摘要和 TXT 导出消费。更新自由页面正文应传 blocks，不直接写 content；PATCH 不支持格式转换。

Markdown 使用 `notebook.create('markdown')` 与 `edit({markdown: source})`。源码字符串最多 200000 个 JS 字符，原样保存在 `markdown` 字段，`content` 由解析器提取；不要直接更新派生正文。格式 ID 和编辑器 ID 均为 `markdown`，插件 ID 分别为 `format-markdown` 与 `markdown-editor`。

插件自己的 `package.json` 在 cordis 字段中声明 `requires.client`，宿主转换为 Cordis `inject`。使用 `ctx.notebook` 的插件必须声明 `notebook`，挂载界面的插件必须声明对应的 `shell` 或 `noteListUI`。使用 React 组件时还需声明 `ui`；挂载、订阅和清理规则见 [React 界面插件开发指南](React界面插件开发指南.md)。`shell.showEditor()` 用于窄屏下从笔记列表进入编辑区。

```js
export default function (ctx, sdk) {
  const input = sdk.el('input', { type: 'search' })
  ctx.noteListUI.mount(ctx, 'filters', input)
  const filter = ctx.notebook.registerFilter(ctx, 'my-search', () => true)
  sdk.listen(input, 'input', () => {
    const query = input.value.toLowerCase()
    filter.update(note => note.title.toLowerCase().includes(query))
  })
}
```

过滤器的存储不暴露给消费者；同一所有者不能重复注册同名过滤器，不同所有者可以使用相同名称。所有过滤器按“同时满足”组合。`update()` 替换当前规则，`dispose()` 提前注销；消费插件停用时自动注销。已释放的句柄不能再次更新，也不能删除后来注册的过滤器。

`notebook.current()` 返回只读副本，`visible()` 返回过滤排序后的只读笔记副本。通过 `edit({title, content, pinned})` 编辑，通过 `flush()` 等待保存完成。界面可调用 `notebook.observe(ctx, render)`，立即渲染一次，再订阅变化；监听随 ctx 自动清理。

## 2. 业务事件使用 Cordis

事件声明以 `@mode` 标记分发约定：`notebook/changed`、`notebook/saved`、`plugins/remote-stop` 使用 `parallel`；`notebook/before-save`、`plugins/before-stop` 使用 `serial`。`test/event-modes.test.js` 轻量检查前端源码中的字面量事件调用及笔记通知包装器，避免误用 `emit` 跳过异步等待；它不覆盖动态计算的事件名，也不改变 Cordis 自身的类型约束。

| 事件 | 参数 | 语义 |
| --- | --- | --- |
| `notebook/changed` | `{reason, selectedId, dirty, busy}` | 编辑、选择、筛选或保存状态变化。`observe()` 使用此事件。 |
| `notebook/before-save` | 只读 Note | 串行、可异步的保存前校验。返回提示文字或抛出错误即可拒绝；返回 undefined、null 或 false 表示通过。 |
| `notebook/saved` | 后端实际返回的只读 Note | PATCH 保存成功后通知；传递该次已保存版本，不保证仍是当前正在编辑的版本。 |
| `plugins/before-stop` | StopRequest | 本页面受管理的停止准备，可异步、可拒绝。 |
| `plugins/remote-stop` | `{targets: string[]}` | 宿主同步到远端已停用的前端插件时，在本页同步卸载前并行通知；用于提示与恢复，不可否决远端操作。 |

`Note` 包含 `id/title/content/pinned/createdAt/updatedAt`，时间为字符串。保存校验使用 `ctx.serial`，第一个拒绝终止后续校验；被拒绝时不提交 PATCH，脏状态和浏览器草稿均保留。

```js
ctx.on('notebook/before-save', note => {
  if (note.title.length > 100) return '这个插件要求标题不超过 100 个字符'
})
ctx.on('notebook/saved', note => {
  preview.textContent = note.content.slice(0, 120)
})
```

变化和成功通知使用 `ctx.parallel` 隔离监听器异常，异常会提示，但不会把已经完成的磁盘保存标记为失败。通知不等待监听器完成，因此不能用于阻止保存。保存前校验不要再次调用 `flush()`，否则会等待自身正在进行的保存。`notebook/saved` 当前覆盖本页笔记服务的 PATCH 保存，不是跨页面、后端 RPC 或创建/删除操作的全局审计事件。浏览器 DOM 点击、输入仍使用正常 DOM 事件。

## 3. 准备停止与资源清理分开

本页面管理器执行停用、前端重载或主题切换的流程：

1. 发出 `plugins/before-stop`，串行等待准备监听器。
2. 笔记服务锁住编辑、新建与选择，等已有业务操作结束，再保存草稿。
3. 全部通过后才发起后端变更或前端重载，并等待本页生命周期同步。
4. 无论成功、拒绝还是请求失败，都逆序执行已登记的释放函数。

```js
ctx.on('plugins/before-stop', async request => {
  lockEditing()
  request.hold(() => unlockEditing()) // 必须在异步操作前登记
  await savePendingWork()           // 抛出错误取消变更
})
ctx.effect(() => () => {
  clearInterval(timer)             // 卸载仅做资源清理，不再尝试保存或拒绝
})
```

`request.reason` 为 `disable/reload/switch/configure`，`targets` 是这次直接操作的插件 ID，不是整个依赖闭包。所有准备监听器均可检查自己的未完成工作；笔记服务保守地保护所有受管理停止。锁保持到变更动作结束；后续监听器拒绝或后端依赖保护拒绝时也会正确解锁。`hold()` 只可在准备监听器完成前调用。原有 `sdk.guard(callback)` 作为兼容入口转接到该事件，原有 `sdk.watch` 也仍可使用。

准备协议只约束发起操作的这个页面，不跨进程、跨标签页进行分布式提交。其他页面停用、直接 API 操作、服务崩溃或浏览器关闭仍可能导致直接卸载；此时不进行迟来的保存检查，不延迟资源清理，未保存内容依靠编辑时写入的浏览器草稿恢复。浏览器存储不可用时会提示。该协议不是 Cordis dispose 的否决钩子。

## 4. 可运行的消费者示例

「保存后摘要」默认关闭，在插件管理器中开启后，正文保存成功会在页面下方显示最近保存的摘要。它只通过 `shell.mount(ctx, 'panels', node)` 挂载界面，以及 `ctx.on('notebook/saved', ...)` 监听事件。停用后节点与监听器自动清理，重新启用从等待下一次保存的状态开始。

源码为 `plugins/note-summary/client.js`，新增此插件只需要增加自己的包清单和实现，无需修改管理器或保存逻辑。`test/notebook-contracts.test.js` 覆盖过滤器生命周期、校验失败、异步保存期间继续编辑、停止保护、强制卸载和摘要插件重复启停。

## 5. 声明与使用配置

插件 package.json 的 `cordis.settings` 声明字段，发现后成为运行时的 `manifest.settings`。管理器自动生成表单，前后端共用 `normalizeConfig()` 校验。字段支持 number、boolean、string，以及 options 枚举；可附加 default、label、description、min、max、step、integer、maxLength。所有值均为基本类型，不接受未知字段；缺少字段用默认值补齐。

```js
settings: {
  mode: 'live',
  fields: {
    length: {
      type: 'number', label: '摘要长度', default: 120,
      options: [{ label: '80 字', value: 80 }, { label: '120 字', value: 120 }],
    },
    showCount: { type: 'boolean', label: '显示字符数', default: true },
  },
}
```

前端插件每次启动从 `sdk.config` 读取只读配置。`mode: 'live'` 必须使用 `sdk.onConfig()` 注册即时应用处理器；处理器随本次激活自动清理。修改前后保持同一个插件实例和界面节点。

```js
const render = () => {
  preview.textContent = savedText.slice(0, sdk.config.length)
}
render()
sdk.onConfig(render)
```

处理器也可以异步执行，签名为 `(config, signal) => Promise<void>`。应支持用旧配置再次调用来补偿失败，不在配置回调中做不可撤销的外部操作。异步操作应遵守 AbortSignal，在继续写入界面前检查 `signal.aborted`；超时、替换和卸载会取消信号，但宿主不能强制终止任意 JavaScript 副作用。

`mode: 'restart'` 在保存设置前执行 `plugins/before-stop`，成功后卸载再激活插件，依赖服务的消费者由 Cordis 随之恢复。新实例读取新配置。自动保存间隔使用此模式验证完整的停止保护与依赖恢复路径；摘要和字数统计使用 live 模式。

设置与启用状态分别存放：`data/plugins-config.json` 保存每个插件的 `{value, revision}`，原有 `plugins-state.json` 仍保存开关。`POST /api/plugins/:id/config` 接收 `{config, expectedRevision}`；版本不符返回 409。已停用插件直接保存，不执行代码。

后端入口为 `(ctx, config, runtime)`：config 是激活时的设置，runtime.config 返回当前只读设置，runtime.onConfig 注册 live 处理器，runtime.dataDir 是已创建的插件专属数据目录。restart 模式重建后端实例和依赖服务的消费者；应用失败时重建为已提交配置。原存储插件继续兼容 notes.json 和旧 file 入口，具体示例见 [Workspace 插件开发指南](Workspace插件开发指南.md) 第 7 节。

已启用插件进入准备事务；若有后端实现，先应用候选配置并检查恢复状态，随后启动 20 秒的页面确认窗口。响应的 preview 仅供发起页面应用前端设置，其他页面快照中的正式配置仍为旧值。后端预览期间服务已经使用候选配置；其他页面暂缓同步这次未确认的后端代次，不能把此机制当作服务副作用的隔离事务。

发起页面确认自身及原来健康的插件恢复正常后，通过 `POST /api/plugins/config/confirm` 发送 `{token, success, error?}`。纯后端插件也走同一确认流程。成功才原子写入配置文件并广播正式配置；失败、确认超时或正常退出均保留已提交值，后端恢复旧配置，前端恢复正式快照并检查结果。恢复失败会明确报错，不声称恢复成功。确认响应丢失时重新读取服务端结果，避免把实际成功误报为回滚。配置恢复不能撤销插件已经执行的外部命令、文件写入或网络请求。

设置窗口独立于重绘的插件卡片；状态刷新不覆盖尚未保存的输入。其他页面更新后，窗口保留输入并显示「载入最新设置」，要求读取新版本后再提交。当前支持内置前端、后端及双端插件；第三方 API v1 暂未接入这一配置协议。
