# 灵感画布插件设计

`studio` 是独立的无限画布应用。文字和图片连接到生成卡片后，由用户或当前工作台 Agent 明确发起生成；编辑和连线不会自动提交图片请求。切换应用或停止生成服务会中断任务，重启不自动重试。

## 插件与依赖

| 插件 | 服务与职责 |
| --- | --- |
| `canvas` | 后端 `canvasDocuments`：画板、素材、版本校验、原子保存、卡片定义注册。前端 `canvasSession`：草稿、保存队列、撤销历史、操作注册。 |
| `canvas-ui` | 前端 `canvasUI`：无限画布、几何交互、卡片视图、工具栏和界面扩展。 |
| `canvas-basic-cards` | 注册文字与图片的数据定义、视图、导入入口、素材列表和图片预览；后端提供 `canvasBasicCards`，保证生成结果的图片类型可用。 |
| `image-generation` | 注册生成卡片；后端 `imageGeneration` 负责图片服务注册、任务队列、取消、输入快照和结果落图。 |
| `image-provider-pixel` | 向生成服务注册 Pixel；独立保存配置，处理请求、代理、错误解释和参考图上传优化。 |
| `canvas-agent-tools` | 通过 `canvasSession` 操作当前画板；保留原有 `studio_*` 工具，增加 `studio_action` 调用扩展操作。 |

基础层不导入卡片、生成任务或 Pixel 的实现。运行时协作通过 `ctx` 服务，公开类型通过提供者包的 `/data`、`/client`、`/server` 类型入口引用。前后端注册表属于各自进程。

`image-generation` 不硬依赖 Pixel。提供者依赖生成服务并注册自己；停用提供者不会卸载画布。停用生成服务前，按宿主依赖保护先停用提供者。停用 Agent 插件不影响手动操作。

## 添加一种卡片

插件声明后端需要 `canvasDocuments`、前端需要 `canvasUI` 和 `canvasSession`。后端注册数据定义，例如：

```js
ctx.canvasDocuments.types.register(ctx, {
  id: 'prompt-template', label: '提示词模板', fields: ['text'], output: 'text',
  defaults: () => ({ text: '' }),
  validate(node) {
    if (typeof node.text !== 'string' || node.text.length > 12000) {
      throw Object.assign(Error('模板文字无效'), { status: 400 })
    }
  },
  resolve: node => ({ text: node.text }),
})
```

前端通过 `canvasUI.register(ctx, { id, label, icon, output, render })` 注册视图，`canvasUI.menu(ctx, { id, label, run })` 登记创建入口。视图可用 `view.field(node, 'text', true)` 接入既有草稿保护；创建使用 `view.add('prompt-template')`。基础卡片插件包含完整示例。

核心保留 `id/type/title/x/y` 及结果来源标记；插件只声明自己的字段。`defaults()` 只能返回声明字段。`validate()` 执行权威数据校验；`resolve()` 将本卡片转换为文字或图片资产引用。生成插件按 `output` 类型汇总有序输入，不依赖具体卡片 ID。当前仅支持有序文字、图片输入，不是自动执行的工作流引擎。

更新卡片使用 `{ type: 'update', id, patch, unset? }`：`patch` 设置字段，`unset` 列出要删除的字段，同一字段不能同时出现在两者中。删除仍受字段权限和卡片校验约束；必填字段不能删除。撤销使用 `unset` 恢复原本缺失的可选字段，避免 `undefined` 在 JSON 传输时丢失；`null` 仍是普通字段值。

注册随 owner 释放。插件缺失时，基础层仍校验公共结构，保留专属字段和连线；界面显示占位卡，可以移动或删除，但不能修改未知专属字段或创建该类型。重新启用后恢复解释。

## 添加图片服务

后端依赖 `imageGeneration`，调用：

```js
ctx.imageGeneration.register(ctx, {
  id: 'my-provider', label: '我的图片服务',
  public: () => ({ model: 'my-model', ratios: ['1:1'], resolutions: ['1k'], referenceImages: true }),
  prepare(input) {
    const privateConfig = readPrivateConfig()
    return {
      model: privateConfig.model,
      generate: (images, signal) => requestImage(input, privateConfig, images, signal),
    }
  },
})
```

`prepare()` 必须同步校验参数、冻结私有配置并返回请求闭包；网络请求在 `generate()` 中进行，返回图片 Buffer，并响应 AbortSignal。私有配置不返回给 `public()` 或任务记录。提供者自己的网络资源通过 owner 清理。

多提供者时，生成卡片显示选择框。旧卡片没有 `provider` 字段时使用当前注册表首个服务；已明确选择的服务缺失时不静默改用其他服务。任务启动后固定提供者、模型、提示词、参考图顺序和参数，后续配置变更只影响新任务。

Pixel 的参考图体积预算、压缩和代理策略属于 Pixel 插件。优化只作用于上传副本，画布保存的素材不改写。

## 用户与 Agent 共用操作

画板编辑、草稿和撤销由 `canvasSession` 管理。生成插件在 `canvasSession.actions` 注册 `generate`，按钮与 `studio_generate` 调用同一入口。新增操作可以登记 `id/label/schema/run`；`studio_read.actions` 列出可用操作，`studio_action` 调用它们。

Agent 修改要求当前 revision 匹配，并且用户没有正在编辑、拖动或待恢复的草稿。服务端再次检查 revision。异步生成结果不会覆盖用户的提示词，而是增加独立图片卡片。自动保存期间仍保留原输入框及其基线，按钮保持单次点击语义。

## 数据与兼容

- 保留 `data/apps/studio/plugin-data/canvas/studio.json` 的 v1 格式，以及同目录下的 `images/`。现有节点、连线、资产 ID 和任务历史继续使用。
- 原 `canvas` 插件 ID 保留；浏览器的画板选择和草稿仍存放在原插件的隔离空间，不迁入界面插件。
- `canvasDocuments.records(namespace)` 提供扩展记录；生成任务的 `image-generation` 空间兼容映射到旧 `jobs` 字段，其他空间使用 `extensions`。调用方不能获得整个可变文档。
- 事务回调同步执行。`tx.records` 修改任务记录，`tx.board(id)` 读取副本，`tx.edit(id, operations)` 执行校验过的画板操作；一起原子提交，失败一起回滚。网络和图片解码在事务外运行。
- 图片文件及资产元数据先保存，任务成功和结果卡片随后在同一事务提交。失败时可能保留可重用素材，但不会把未落图的任务错误标记为已成功。达到卡片上限时明确提示图片留在素材库。
- Pixel 私有配置保存到 `plugin-data/image-provider-pixel/pixel-private.json`。首次没有新文件时，通过基础层的服务端兼容接口读取旧 `canvas/pixel-private.json`；旧文件保留。新文件存在后不再次导入。没有旧文件时才首次导入环境或本机 Pixel 配置。备份应包含两个插件目录。
- 已有 `/api/studio`、画板/素材/编辑路由和生成/取消/配置路由保留；后几项现在由所属插件注册，停用后对应路由不可用。

生成服务启动时把遗留 queued/running 任务标为 interrupted。停止服务或提供者时取消相关任务，忽略迟到结果，不自动重新计费。请求 ID 在文档事务内去重。配置文件写入和已经发生的上游计费不能由插件回滚。

## 开发与验证

```powershell
pnpm install
pnpm workbench
# 在“切换应用”中选择“灵感画布”

pnpm test:plugin --app studio --plugin image-generation
pnpm test:plugin --app studio --plugin image-provider-pixel
pnpm build studio
```

开发模式继续由 Vite 和 Cordis 热更新：视图更新不重建后端生成任务；后端生成服务或提供者更新会中断对应任务。`plugins/before-stop` 先保存草稿和视角，释放阶段清理监听器、视图、注册项和请求。正式运行需构建后重启。

`test/studio-client.test.js` 验证用户/Agent 交互和视图启停；`studio-model` 验证历史保护、图片协议和上传优化；`studio-plugins` 验证扩展卡片、原子事务、提供者移除及配置迁移；`studio-runtime` 使用本机模拟图片服务器验证 HTTP、持久化和应用切换。测试不调用真实付费生图接口。
