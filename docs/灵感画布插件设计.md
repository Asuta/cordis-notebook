# 灵感画布插件设计

`studio` 是独立的无限画布应用。文字、图片和视频连接到生成卡片后，由用户或当前工作台 Agent 明确发起生成；编辑和连线不会自动提交请求。WaveSpeed 的远端任务可暂停和恢复查询；Pixel 中断后仍需手动重试。

## 插件与依赖

| 插件 | 服务与职责 |
| --- | --- |
| `canvas` | 后端 `canvasDocuments`：画板、素材、版本校验、原子保存、卡片定义注册。前端 `canvasSession`：草稿、保存队列、撤销历史、操作注册。 |
| `canvas-ui` | 前端 `canvasUI`：无限画布、几何交互、卡片视图、工具栏和界面扩展。 |
| `canvas-basic-cards` | 注册文字、图片、视频定义与视图，导入、素材库、图片预览、视频播放和下载；后端提供 `canvasBasicCards`。 |
| `image-generation` | 注册生成卡片、动态模型参数和统一参考列表；后端 `imageGeneration` 负责服务注册、队列、输入快照、恢复查询和图片/视频结果落盘。 |
| `image-provider-pixel` | 向生成服务注册 Pixel；独立保存配置，处理请求、代理、错误解释和参考图上传优化。 |
| `image-provider-wavespeed` | 全量图片/视频模型目录与 schema 校验、ticket 上传、提交和轮询；账户隔离的缓存、私有配置与恢复查询。 |
| `canvas-agent-tools` | 通过 `canvasSession` 操作当前画板；保留原有 `studio_*` 工具，增加 `studio_action` 调用扩展操作。 |

基础层不导入卡片、生成任务或 Pixel 的实现。运行时协作通过 `ctx` 服务，公开类型通过提供者包的 `/data`、`/client`、`/server` 类型入口引用。前后端注册表属于各自进程。

`image-generation` 不硬依赖具体提供者。提供者依赖生成服务并注册自己；停用提供者不会卸载画布。停用生成服务前，按宿主依赖保护先停用提供者。停用 Agent 插件不影响手动操作。

## 添加一种卡片

插件声明后端需要 `canvasDocuments`、前端需要 `canvasUI` 和 `canvasSession`。后端注册数据定义，例如：

```js
ctx.canvasDocuments.types.register(ctx, {
  id: 'prompt-template', label: '提示词模板', fields: ['text'], output: 'text',
  defaults: () => ({ text: '' }),
  validate(node) {
    if (typeof node.text !== 'string' || node.text.length > 12000) {
      throw Object.assign(Error('模板文字无效'), { status: 400 })
    }
  },
  resolve: node => ({ text: node.text }),
})
```

前端通过 `canvasUI.register(ctx, { id, label, icon, output, render })` 注册视图，`canvasUI.menu(ctx, { id, label, run })` 登记创建入口。视图可用 `view.field(node, 'text', true)` 接入既有草稿保护；创建使用 `view.add('prompt-template')`。基础卡片插件包含完整示例。

核心保留 `id/type/title/x/y` 及结果来源标记；插件只声明自己的字段。`defaults()` 只能返回声明字段。`validate()` 执行权威数据校验；`resolve()` 将本卡片转换为文字或图片/视频资产引用。生成插件按 `output` 类型汇总有序输入，不依赖具体卡片 ID。当前支持文字、图片、视频输入，由用户明确启动生成。

更新卡片使用 `{ type: 'update', id, patch, unset? }`：`patch` 设置字段，`unset` 列出要删除的字段，同一字段不能同时出现在两者中。删除仍受字段权限和卡片校验约束；必填字段不能删除。撤销使用 `unset` 恢复原本缺失的可选字段，避免 `undefined` 在 JSON 传输时丢失；`null` 仍是普通字段值。

注册随 owner 释放。插件缺失时，基础层仍校验公共结构，保留专属字段和连线；界面显示占位卡，可以移动或删除，但不能修改未知专属字段或创建该类型。重新启用后恢复解释。

## 添加图片或视频生成服务

后端依赖 `imageGeneration`，调用：

```js
ctx.imageGeneration.register(ctx, {
  id: 'my-provider', label: '我的图片服务',
  public: () => ({ model: 'my-model', ratios: ['1:1'], resolutions: ['1k'], referenceImages: true }),
  prepare(input) {
    const privateConfig = readPrivateConfig()
    return {
      model: privateConfig.model,
      generate: (images, signal) => requestImage(input, privateConfig, images, signal),
    }
  },
})
```

`prepare()` 必须同步校验参数、冻结私有配置并返回请求闭包；网络请求在 `generate()` 中进行，并响应 AbortSignal。返回图片 Buffer 的旧协议继续可用，也可返回 `{ bytes: Buffer, kind: 'image' | 'video', name? }[]`。实际参数和参考绑定可通过 PreparedGeneration.parameters/bindings 写入任务快照。私有配置不返回给 `public()` 或任务记录。提供者自己的网络资源通过 owner 清理。

目录型服务在 `public()` 返回 modelCatalog、catalogVersion，在服务上实现 listModels/getModel。模型定义提供 schema、fields、mediaFields、defaults、outputKind 和 supported/unsupportedReason。前端按 schema 渲染，服务端再次校验。WaveSpeed 支持本地 $ref、allOf、nullable 及 JSON Schema draft 7/2019/2020；无法调用的定义明确报错，不猜测请求格式。

生成卡片扩展字段：provider、model、modelParameters、references、referenceOrder、referenceBindings。modelParameters 和 referenceBindings 按「provider:model」分组；references 为卡片内 `{id, assetId}`，referenceOrder 使用 `direct:id`/`edge:id` 统一排序卡片内与连线素材。GenerationInput.references 固定记录来源、顺序和类型，bindings 把参考 key 映射到模型媒体字段 path。每份参考都必须被分配；多个同类字段要求显式绑定，单字段可自动分配，数组按统一顺序填入。

可恢复服务还实现 resume(job)。在首次提交前用 generate 第三个参数中的 checkpoint 保存 submitting，拿到远端 ID 后先持久化 submitted/taskId/account，再查询。checkpoint 只接受白名单字段，不保存 Key 或签名 URL。提交结果未知时标为 uncertain；已有远端 ID 时标为 paused。resume 只查询同一远端任务，不能重新提交。WaveSpeed 的账户指纹校验、原签名 PUT 和结果下载属于提供者实现。

多提供者时，生成卡片显示选择框。旧卡片没有 `provider` 字段时使用当前注册表首个服务；已明确选择的服务缺失时不静默改用其他服务。任务启动后固定提供者、模型、提示词、参考图顺序和参数，后续配置变更只影响新任务。

Pixel 的参考图体积预算、压缩和代理策略属于 Pixel 插件。优化只作用于上传副本，画布保存的素材不改写。

## 用户与 Agent 共用操作

画板编辑、草稿和撤销由 `canvasSession` 管理。生成插件注册 generate、models、model、resume、detach，按钮与 Agent 使用同一入口。新增操作可以登记 `id/label/schema/mutates/run`；只读目录操作声明 mutates=false。`studio_read.actions` 列出可用操作，`studio_action` 调用它们。原有 10 个工具名保留，studio_import_image 可导入图片或视频，studio_inspect_image 仍仅检查图片。

Agent 修改要求当前 revision 匹配，并且用户没有正在编辑、拖动或待恢复的草稿。服务端再次检查 revision。异步生成结果增加独立图片/视频卡片。动态参数也接入相同草稿、冲突保护和撤销机制；非法 JSON/数字保留当前页面原文并阻止生成。自动保存期间保留原输入框及其基线，按钮保持单次点击语义。

## 数据与兼容

- 保留 `data/apps/studio/plugin-data/canvas/studio.json` 的 v1 格式，以及同目录下的 `images/`，新增 `videos/`。旧资产缺少 kind 时按图片处理，现有节点、连线、资产 ID 和任务历史继续使用。
- 原 `canvas` 插件 ID 保留；浏览器的画板选择和草稿仍存放在原插件的隔离空间，不迁入界面插件。
- `canvasDocuments.records(namespace)` 提供扩展记录；生成任务的 `image-generation` 空间兼容映射到旧 `jobs` 字段，其他空间使用 `extensions`。调用方不能获得整个可变文档。
- 事务回调同步执行。`tx.records` 修改任务记录，`tx.board(id)` 读取副本，`tx.edit(id, operations)` 执行校验过的画板操作；一起原子提交，失败一起回滚。网络和图片解码在事务外运行。
- 媒体文件及资产元数据先保存，各份输出 ID 逐个记录；任务成功和结果卡片随后在同一事务提交。失败时可能保留可重用素材；恢复查询会复用已落盘输出。达到卡片上限时明确提示结果留在素材库。
- Pixel 私有配置保存到 `plugin-data/image-provider-pixel/pixel-private.json`。首次没有新文件时，通过基础层的服务端兼容接口读取旧 `canvas/pixel-private.json`；旧文件保留。新文件存在后不再次导入。没有旧文件时才首次导入环境或本机 Pixel 配置。备份应包含两个插件目录。
- 已有 `/api/studio`、画板/素材/编辑路由和生成/取消/配置路由保留；后几项现在由所属插件注册，停用后对应路由不可用。

新增 HTTP 接口（前缀 /api/studio）：

| 接口 | 用途 |
| --- | --- |
| GET /providers/:id/models?q=&kind=&type=&offset=&limit=&refresh=1 | 搜索、筛选和刷新模型目录。 |
| GET /providers/:id/model?id= | 读取模型参数定义。 |
| POST /wavespeed/config | 保存私有配置，空 Key 保留原值。 |
| POST /resume、/detach，body={id} | 恢复原任务查询、结束本地跟踪。 |
| POST /media/uploads，body={name,size} | 创建视频临时上传。 |
| POST /media/uploads/:id，body={offset,base64} | 每块最多 1 MB，按 offset 写入。 |
| POST /media/uploads/:id/finish、/abort | 校验并保存视频，或清理上传。 |
| GET/HEAD /videos/:assetId | 播放或下载原视频，支持单 Range、206/416。 |

视频上限 200 MB，支持 MP4/WebM，服务端解析容器并校验视频轨道、尺寸和时长，不依赖 ffmpeg。上传使用系统临时目录，限制 3 项/400 MB，一小时无操作后清理；停用插件也清理。图片仍使用原有 20 MB 上传入口。客户端通过 canvasSession.uploadMedia/mediaKind/mediaUrl 复用媒体能力，不能跨插件相对路径导入实现文件。

生成服务启动时，遗留 queued/running 按远端状态转为 paused（有 ID）、uncertain（提交结果未知）或 interrupted。关闭服务或停用提供者会暂停相关任务；重启恢复有 ID 的原任务查询，用户手动暂停则等待手动恢复。不自动重发 POST，迟到的提交响应仍尽量保存远端 ID。请求 ID 在文档事务内去重，同一卡片有未结束任务时禁止重复生成。配置文件写入和已经发生的上游计费不能由插件回滚。

## 开发与验证

五类扩展已有完整脚手架：[开发路径与验收边界](../applications/studio/development/README.md)。在工作台用 workspace_development_info({task:"studio-action" | "studio-card" | "studio-provider" | "studio-agent-action" | "studio-extension"}) 取得参数和对应模板，再调用推荐脚手架。另有 studio-provider-advanced 和 studio-settings 两个配方任务，复用 studio-provider 并附带入口切换说明。生成服务声明了 server:imageGeneration 能力，可直接读取契约和短示例。模板默认停用，附带 README 和可执行测试。

studio-extension 使用 extend 的 card/refresh/dispose 钩子：既有卡片和复用的 video DOM 需在 refresh 中补挂载，以插件标记去重，停用时清理按钮和侧栏。设置配方通过 canvasUI.settings 组合到同一插件，使用 runtime.dataDir 与 writeSnapshot，带 revision 冲突检查，公开响应不含 Key。HTTP 进阶配方先保存任务阶段和远端 ID，再轮询；resume 仅查询原任务。本地 mock 验收与真实服务验收分别报告。

客户端写动作共用生成到插件内部的 mutation.js：保存已有草稿，锁定画板和 revision，阻止重复操作，异步结束后再次检查可编辑状态与 owner，最后一次原子提交并保留历史。Agent schema 用于发现，动作自身仍需校验参数。公共浏览器场景区分菜单生命周期、默认重命名示例、新卡片生命周期和服务选择；provider 场景不生成，真实生成需要单独授权与验证。`test/studio-development-assets.test.js` 检查资料发现、脚手架、卡片停用保护、模拟生成任务以及 Agent 操作协议，浏览器部分通过 CORDIS_BROWSER_TEST=1 启用。

```powershell
pnpm install
pnpm workbench
# 在“切换应用”中选择“灵感画布”

pnpm test:plugin --app studio --plugin image-generation
pnpm test:plugin --app studio --plugin image-provider-pixel
pnpm test:plugin --app studio --plugin image-provider-wavespeed
pnpm build studio
```

开发模式继续由 Vite 和 Cordis 热更新：视图更新不重建后端生成任务；后端更新后按上述任务状态恢复。`plugins/before-stop` 先保存草稿和视角，释放阶段清理监听器、视图、注册项和请求。正式运行需构建后重启。

`test/studio-client.test.js` 验证用户/Agent 交互、模型参数草稿和统一排序；`studio-model` 验证历史保护、图片协议和上传优化；`studio-plugins` 验证扩展、原子事务及配置迁移；`studio-runtime` 验证 HTTP、持久化和应用切换。新增 studio-wavespeed 验证目录、schema、签名上传、恢复和不确定提交，studio-wavespeed-runtime 使用真实 MP4/WebM 及本机模拟 HTTP，studio-wavespeed-browser 使用 Chromium 检查完整交互。所有测试均使用隔离数据，不调用真实付费生成。
