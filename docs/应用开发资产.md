# 应用维护的开发骨架与公共验收

开发资料默认仍展开完整契约与示例。工作台负责校验、原子发布、执行和记录；各应用在自己的 `development.json` 声明扩展骨架与公共验收入口，不在工作台增加应用专属分支。

## 骨架

`templates` 条目可声明 `file`，指向应用目录内的模板 JSON。`tasks` 的 `scaffold` 指向推荐模板 ID；模板也可通过 `task` 复用该任务的资料。`workspace_development_info` 返回 `recommendedScaffold` 和参数说明。

模板 JSON 含 `parameters`（字符串默认值、说明、可选正则）和 `files`（插件内输出路径到应用内源文件路径）。源文件用 `{{id}}` 插入经过验证的插件 ID；文本或字符串字面量使用 `{{name:json}}` 等 JSON 转义。内置参数为 `id/name/appId/description`，不可覆盖。输出路径不能越界，发布前仍检查清单、依赖提供者与构建输入。失败不发布半份插件，也不覆盖已有插件。

笔记应用的 `note-editor` 模板是文本格式的完整接入示例。它包含双端格式注册、editorHost、notebook.edit、owner 生命周期、限定到插件的样式和格式规范化测试；`parameters.field/editorLabel` 来自需求。复杂格式可修改生成代码。生成成功不代表用户功能或浏览器测试通过。

`note-action` 模板把操作接入层与业务分开：`client.js` 负责工具栏菜单挂载、选择订阅、无选择/忙碌/不可编辑时的禁用、异步防重入和 owner 释放；`action.js` 提供 `label/mode/supports/run`。参数 `actionLabel` 是名称，`mode` 为 `read` 或 `edit`。默认业务只提示当前标题，开发者仍须实现用户需求。`run({note,update,notify})` 获得点击时的笔记，`await update(patch)` 校验 owner 和当前选择后调用 notebook.edit/flush，防止异步结果写到另一篇笔记；notify 在 owner 释放后不再提示。格式专属字段由业务的 supports/run 处理，不在工作台硬编码。

## 公共验收

`verification` 按 ID 声明应用内的场景 JSON；任务通过 `verification` 数组选择相关场景。资料工具返回参数、覆盖范围和 `browser_scenario` 用法。

场景 JSON 包含 `parameters/coverage/steps`。字符串中的 `{{参数名}}` 按数据替换，不执行 JavaScript；步骤仅允许已支持的 `browser_action`，最多 80 步、整批 60 秒。`reload` 是真实页面刷新并等待宿主就绪。稳定入口由应用维护，不允许传任意脚本、应用或外部地址。

先 `browser_open`，再用 `browser_plugin` 在独立实例启用插件，然后执行场景。所有操作仍通过真实浏览器；逐步记录场景 ID、源文件 SHA256、展开后的参数、断言和失败现场。首个失败停止后续步骤；场景不自动结束验收，也不消除旧失败。业务特有规则仍需补断言，最后调用 `browser_finish`；需要复测时保留此前结果并使用独立实例。

`note-editor-lifecycle` 覆盖文本格式创建、自动保存后刷新、普通格式切换、空正文刷新、停用移除菜单、重新启用唯一入口和再次编辑保存。它依赖笔记应用的标准布局及插件管理界面；这些入口变化时由应用维护者更新场景。复杂编辑器或替代布局不适用此场景。

`note-action-lifecycle` 需要全新空实例，参数为 pluginId/actionLabel/formatName（默认普通笔记）。覆盖无选择禁用、创建与切换后的可用性、停用移除、重新启用唯一入口和刷新恢复；结束时关闭菜单、返回选中笔记的页面结构，方便继续业务验证。场景不点击业务动作，不能证明剪贴板或正文等业务结果正确。`assertion:disabled` 检查唯一可见交互控件的原生 disabled 或 aria-disabled 状态；缺失、隐藏或普通文本不算“未禁用”。

新增骨架与场景须通过真实构建和浏览器测试；运行 `pnpm test:browser` 包含这一验证。固定 Agent 评测仍使用独立的 `scripts/agent-benchmark/acceptance.js`，公共场景不能修改评测通过标准。

## 刷新与诊断

开发服务器每次整页刷新生成新的 reloadToken；HTML 带有对应批次，页面桥接固定回报文档加载时的值。工作台以文档批次确认就绪，避免先收到新页面、后收到刷新事件时再次等待。真正未就绪的页面仍等待；超时返回 PAGE_REBIND_PENDING，同一刷新不会每次重置时限。启用结果及 workspace_status 的 rebind 记录包含最近一次等待的耗时和批次。重新发送任务不会绕过应用 session 校验。

浏览器断言保留实际值、匹配数量、可见性、尺寸、display/visibility 和 failedCondition。文字相符但目标容器无尺寸时明确报 visibility，不能把不可见文字当成功，也不能修改断言掩盖原失败。
