# 笔记格式插件开发指南

当前格式注册协议用于内置插件扩展：前后端分别注册同一个格式 ID，通用笔记服务通过注册表处理数据。第三方 API v1 的子进程协议尚未提供后端格式注册 RPC；不要把仅注册前端格式理解成已经支持后端保存。

## 结构与职责

- `plugins/note-formats/registry.js`：注册、所有者清理、通用字段校验、正文提取与保存字段选择，不包含具体格式分支。
- `plugins/note-formats/note.js`：格式服务内部的旧笔记类型兼容和深只读快照实现；外部调用 ctx.noteFormats.typeOf()、snapshot()。
- `plugins/format-plain/format.js`、`plugins/format-freeform/format.js`、`plugins/format-markdown/format.js`：三种格式的数据定义、默认数据、校验和文本提取。
- `plugins/note-formats/server.js`、`plugins/note-formats/client.js`：各自提供 `ctx.noteFormats`。
- `plugins/format-*/server.js`、`plugins/format-*/client.js`：同一插件目录中的前后端注册入口。
- 编辑器仍是独立插件，通过 `editorHost.register(ctx, editorId, node)` 提供视图。格式中的 editor 字段关联视图；停用编辑器不代表停用数据格式。

格式插件依赖 noteFormats；通用笔记服务只依赖注册服务，不依赖具体格式。这样停用一种格式不会停止所有笔记功能。前端格式入口通过宿主已有的后端就绪门等待同一插件的后端启动，后端停用后前端注册随之撤销。没有改变已有插件安装协议。

## 声明一种新格式

例如 `plugins/format-checklist/format.js`（示例，未安装到产品）：

```js
export const checklist = {
  type: 'checklist',
  label: '清单笔记',
  icon: '☑',
  editor: 'checklist',
  fields: ['items'],
  defaults: () => ({ items: [] }),
  normalize(data) {
    if (!Array.isArray(data.items) || data.items.length > 1000) throw new Error('清单无效')
    return { items: data.items.map(item => {
      if (!item || typeof item.text !== 'string' || typeof item.done !== 'boolean') throw new Error('清单项无效')
      return { text: item.text, done: item.done }
    }) }
  },
  toText: data => data.items.map(item => (item.done ? '[x] ' : '[ ] ') + item.text).join('\n'),
}
```

`fields` 是该格式可读写的数据字段，不包含 id/type/title/pinned/createdAt/updatedAt 等公共字段。字段不得重复或使用原型相关名称。正文为唯一特殊字段：纯文本格式可以将 content 声明为数据字段，其他格式的 content 从 toText 派生。`normalize` 和 `toText` 必须同步执行，数据必须是可序列化的 JSON。输入提供深冻结副本；不要修改输入或执行文件、网络等副作用。

注册表验证标题最多 200 个 JS 字符、正文最多 200000 个 JS 字符、pinned 为布尔值；格式作者负责数据结构和集合上限。未声明的 PATCH 字段会被拒绝。PATCH 不能转换 type，也不能提供与派生文本不一致的 content。

后端入口 `plugins/format-checklist/server.js`：

```js
import { checklist } from './format.js'
export const formatChecklist = {
  inject: ['noteFormats'],
  apply(ctx) { ctx.noteFormats.register(ctx, checklist) },
}
```

前端入口 `plugins/format-checklist/client.js`：

```js
import { checklist } from './format.js'
export default function(ctx) { ctx.noteFormats.register(ctx, checklist) }
```

在新插件 package.json 的 cordis 字段声明前后端入口及 noteFormats 服务依赖，并添加 browser/node 两个 bundle 任务。参考 plugins/format-plain/package.json。再新增编辑器插件，依赖 notebook、editorHost 并注册 checklist 编辑器。编辑时调用 ctx.notebook.edit({ items })；通用保存、草稿、新建菜单均无需增加分支。

构建会把本插件的 format.js 分别合入 dist/client.js 与 dist/server.js，public 只公开 client.js。样式和静态资源另声明 copy 任务与 public。相对导入只能引用本插件源码；其他插件通过服务调用。完整规则见 [Workspace 插件开发指南](Workspace插件开发指南.md)。

Markdown 是完整的格式扩展示例：格式数据只有 `markdown` 源码字段，`content` 由解析后的文本派生；编辑器仅调用 `notebook.edit({ markdown })`，无需修改通用保存、草稿或新建菜单。前后端分别由 markdown 插件提供解析服务；格式插件以 createMarkdownFormat(ctx.markdown) 构造声明，编辑器调用 ctx.markdown.render()。支持表格、删除线和任务列表，禁用原始 HTML。

解析器源码在 `plugins/markdown/parser.js`，依赖 [markdown-it](https://github.com/markdown-it/markdown-it)。`pnpm build` 分别构建 `plugins/markdown/dist/client.js`（浏览器）和 `dist/server.js`（Node 入口，本包解析逻辑合入其中，npm 依赖保持 external），生成文件不纳入版本控制。新增或修改 npm 解析依赖后必须重新构建；不能直接在浏览器独立插件里导入裸包名。`pnpm start`、`pnpm dev`、`pnpm test` 都会先构建。

## 生命周期和缺失格式

`register(owner, definition)` 返回释放函数，且自动随 owner 卸载。同一 type 重复注册会报错。`get(type)` 返回声明或 undefined；`list()` 返回已注册声明；`observe(owner, handler)` 立即调用一次，此后在注册或注销时通知，监听随 owner 清理。

停用格式后，新建菜单移除对应选项；已有笔记仍可列出、搜索、导出 JSON、删除，但不可编辑。后端拒绝缺少格式的创建和更新（409），不会剥离未知字段或把未知笔记当普通文本保存。重新启用即可恢复编辑。旧笔记无需批量迁移，原有 type/blocks/content 存储结构不变。

如果浏览器仍有待恢复草稿但其格式缺失，草稿保持原样，状态栏提示启用格式；为了避免覆盖同标签页唯一草稿，暂时禁止编辑，仍可浏览笔记。格式重新注册后尝试恢复，恢复成功后沿用原来的保存队列。JSON 导出适用于所有格式，也适用于当前缺失的格式；尚无 JSON 导入界面。

验证：`pnpm test` 包括第三种格式的后端保存、重启后未知数据保留、注销/重注册、前端嵌套数据保存与草稿恢复，以及原有普通笔记和自由页面测试。新增格式还应在独立数据目录中验证真实编辑器、动态菜单及启停。
