# 块页面设计与使用

在笔记列表点击「新建」→「块页面」，即可使用 Notion 风格的流式编辑页面。格式由 `applications/notebook/plugins/format-block` 注册，界面由 `applications/notebook/plugins/block-editor` 提供；两个插件默认启用。它与支持自由坐标的「自由页面」是独立格式，不会转换或覆盖已有笔记。

## 编辑操作

- 在空块输入 `/` 打开块菜单，也可以点工具栏「插入」或块旁的 `+`。菜单提供正文、三级标题、项目/编号列表、待办、折叠、引用、提示块、代码、分割线、表格和图片。
- Enter 新建块，Shift+Enter 块内换行；Tab / Shift+Tab 嵌套或取消嵌套。在表格里 Tab 切换单元格。
- 拖动块旁的 `⠿` 调整顺序或嵌套；Alt+Shift+↑/↓ 移动块，Ctrl/Cmd+Shift+D 复制块。
- 点击待办或折叠标记切换状态；Ctrl/Cmd+Enter 切换当前待办/折叠块。
- 工具栏提供粗体、斜体、下划线、删除线、行内代码、高亮和链接。Ctrl/Cmd+Z 撤销，Ctrl/Cmd+Shift+Z 重做。撤销历史属于当前编辑器实例，刷新或切换笔记后不保留。
- 沿用应用的自动保存、Ctrl/Cmd+S 保存和草稿保护。图片通过 note-assets 上传；JSON 文档引用图片地址，备份时还需保存图片资源。

## 数据与集成

`note.type` 是 `block`。正文原始数据为 `document: { version: 1, blocks: [...] }`，块包含稳定 `id`、`type`、富文本 `body`、`checked`、`collapsed` 和嵌套 `children`。`body` 使用应用的 OutlineDocument；Tiptap JSON 仅用于编辑器内部转换。`content` 是派生纯文本，供搜索、摘要、字数和文本导出使用。

通过 `blockDocument.create/normalize/text` 创建、校验和提取正文，通过 `notebook.edit({ document })` 或带 revision 的 `notebook_update` 修改。Agent 局部结构编辑优先使用下述块级工具。不要直接改 notes.json。旧版同结构块页面无需迁移；停用格式时保留原数据，恢复格式后可继续编辑。不提供其他格式原地转换或 JSON 导入界面。

文档最多 1000 块、12 层子块、200000 个正文字符（包含块分隔开销），序列化大小最多 1750000 字节。格式与树操作测试见 `test/block-page.test.js`，真实编辑器快捷键、嵌套和粘贴测试见 `test/block-page-interaction.test.js`。

## Agent 按块编辑

默认启用的「块页面 Agent 工具」（`block-agent-tools`）提供两个页面工具，不需要 Agent 重写整篇 document。它依赖 notebook 和 blockDocument；停用块格式时块工具退出，恢复后重新注册，普通笔记工具不受影响。

先用 `notebook_open({id})` 打开目标块页面，或 `notebook_create({type:"block",title:"计划"})` 创建，再调用 `notebook_blocks_read({})`。返回当前草稿的 `id`、`revision` 和 `blocks` 树，每块含 ID、类型、文字、状态和 children。`includeBody:true` 还返回每块的富文本 body。这个 revision 与通用 notebook_read 使用同一协议。

`notebook_blocks_edit({id,revision,operations})` 支持：

| 操作 | 参数与含义 |
| --- | --- |
| insert | `block:{id?,type?,text?,body?,level?,checked?,collapsed?}`；默认创建正文块，ID 可自动生成。位置默认 end。 |
| update | `blockId,patch`；仅改提供的字段，保留块 ID 和 children。checked 仅用于 todo，collapsed 仅用于 toggle，level 仅用于 heading（1–3）。 |
| remove | `blockId`；删除块及全部子块；删空页面时保留一个稳定 ID 的空正文块。 |
| move | `blockId,placement,targetId?`；整棵子树一起移动，拒绝放到自身或后代中。 |

insert/move 的位置：before/after 是目标同级前后；inside 放在目标的子块末尾并展开目标；start/end 放在页面顶层首尾，不接受 targetId。取消嵌套可把子块移动到其父块的 after，或者顶层 start/end。

例如，读取返回笔记 ID 为 `note-1`，页面已有块 `intro`，用实际返回的 revision 替换下面的占位符：

```json
{
  "id": "note-1",
  "revision": "刚读取的 revision",
  "operations": [
    {"op":"insert","block":{"id":"task-1","type":"todo","text":"检查结果"},"targetId":"intro","placement":"after"},
    {"op":"update","blockId":"task-1","patch":{"checked":true}},
    {"op":"move","blockId":"task-1","targetId":"intro","placement":"inside"}
  ]
}
```

每批 1–100 个操作，顺序执行于副本，全部校验通过后才调用 model.edit 和 flush；任何参数或文档上限错误都不会产生部分修改。返回最新块树、revision 和 insertedIds，可供下一批继续使用。若用户继续输入、切换笔记或发生版本冲突，应重新读取后决定如何修改，不能自动换 revision 重试旧操作。保存失败时本地草稿会保留，整批写入不保证已持久化，先读取并解决保存问题。

text 会替换该块全部正文并清除正文格式，子块不变；保留富文本需先 includeBody:true，修改该块完整 body。text/body 不能同时提供。转换 type 必须明确提供 text 或 body。空表格用 `{type:"table"}` 创建，修改单元格用 body；图片 text 必须是已上传的本地资源地址。块级结构修改沿用外部更新的历史边界，不能靠 Ctrl+Z 回到旧页面快照；单段选区改写优先使用 replace_selection。

回归覆盖见 `applications/notebook/plugins/block-agent-tools/test/block-agent-tools.test.js`：真实笔记模型和 Agent 桥接、草稿读取、版本保护、批次原子校验、保存失败、服务停用恢复及格式上限。测试由 `workspace_test({plugins:["block-agent-tools"]})`、`pnpm test:plugin --app notebook --plugin block-agent-tools` 和 `pnpm test` 自动发现。
