# Agent 完整开发评测

此工具评测“收到需求 → 完成插件 → 固定验收通过”，不是只测首次写代码。入口为 `pnpm benchmark:agent`，不修改业务框架，不提交、推送或安装依赖。

## 固定任务与验收

任务、提示词和完整检查 ID 在 `scripts/agent-benchmark/cases.js`；独立验收在 `acceptance.js`。当前有六个任务（其中两个操作类任务用于检验通用性）：

| 任务 ID | 应用 | 验收内容 |
| --- | --- | --- |
| content | notebook | 无选择、普通正文即时计数、空正文、Markdown 源码语义、切换与插件启停 |
| action | notebook | 无选择时禁用、复制当前标题、反馈、切换后复制、插件启停 |
| date-action | notebook | 普通/Markdown 原文末尾插入本地日期、连续点击、空正文、切换、持久化与刷新、插件启停 |
| editor | notebook | 新建格式、body 自动保存、切换、刷新恢复、清空保存、重新启用后可编辑 |
| canvas | studio | 连续创建卡片、撤销、刷新保留、插件启停 |
| backend | notebook | 空库、多格式统计、置顶变化、删除、只读、接口启停 |

所有任务检查页面异常，验收前运行 `test:plugin` 的类型契约检查、正式构建、产物校验及插件/关联测试。类型检查不覆盖全部 JavaScript 运行实现；插件自带测试缺失等 coverage.gaps 仍保留。固定验收通过只代表这些场景通过，不代表视觉或任意业务完整覆盖。

`date-action` 独立验收把浏览器本地时间固定为另一天，并保持计时器正常运行，防止把开发当天的日期写死。它检查真实 content/markdown 持久化值，而非仅检查提示或截图。公共生命周期场景不参与判定业务是否通过。进行版本对照时两版应使用同一份当前验收器；旧报告的指纹不同，不能直接计算加速比例。

提示词明确少量稳定的可访问名称/测试标识，以便固定验收；与早期自由提示词首次编辑实验不是同一口径，不能直接比较百分比。Agent 自己执行的 browser_report 作为独立证据保留，不决定固定验收的通过标准。

## 运行

```powershell
# 只看任务，不读取密钥、不启动模型
pnpm benchmark:agent --list

# 默认六个任务各一次，Flash + High，每任务总计最多 600 秒，失败最多返工一次
pnpm benchmark:agent

# 选择任务并重复；任务顺序逐轮轮换
pnpm benchmark:agent --cases "content,action,editor" --repeat 3 --timeout 600 --repairs 1

# 从现有配置加载同一提供者与密钥；模型参数显式固定
pnpm benchmark:agent --config .workbench/config.json --model deepseek-flash --effort high

# 在 Codex 内置浏览器打开控制台输出的 READY 地址，连接后才计时
pnpm benchmark:agent --cases backend --page external

# 工具自身的单元与完整集成测试，不调用真实模型
pnpm test:benchmark
```

默认使用自动化浏览器连接工作台，适合无人值守重复运行；调试可使用 `--page external` 配合 Codex 内置浏览器。固定验收由单独 Playwright 进程执行。真实评测会调用现有配置的模型服务，产生正常模型用量；工具自身集成测试使用本地模拟 Agent，不消耗模型用量。

每轮复制当前 Git 跟踪源码和未忽略的新文件，包含暂存、未暂存改动与删除；记录源码 SHA256、HEAD、任务/验收指纹、模型参数和运行环境。已有同名目标插件只从副本排除，原项目保留。评测实现和参考答案不会复制到 Agent 项目。每轮是全新代码副本、Git 基线、会话、应用数据与端口。插件依赖通过链接复用已安装 node_modules，因此这是可信本地开发隔离，不是安全沙箱；不支持评测期间安装/修改共享依赖。

模型配置在整批开始时冻结，临时配置和 Pi auth 在每轮 finally 中删除。不要强杀运行器；Ctrl+C 走取消与清理流程。异常断电/进程强杀后应检查输出目录中的临时凭据。原始工作区源码发生变化会将整批标记为 invalid，不能用于性能比较。测量期间不要并行构建或运行回归测试。

## 计时和失败规则

- 完成耗时从首次发送任务到固定验收全部通过，包含模型、工具、Agent 自测、外部验收和反馈返工。复制、初始构建及连接浏览器不计入。每任务一个总时限，不在返工时重置。
- `firstEditMs` 是首次成功 write/edit 业务源码工具调用的开始时间，排除脚手架、测试、其他插件。使用命令写文件时可能为空；另报轮询观测到业务源码变化的 `firstObservedCodeChangeMs`，这是上界，不冒充精确首次编辑时间。
- 模型等待与流式输出按已有模型轨迹统计；工具执行按区间并集合并，另列 Agent 浏览器工具与外部固定验收耗时。阶段可能重叠，不能简单相加。网络/服务排队计入模型等待，不能都解释成“思考”。
- 首次通过率分母为全部已开始轮次，包括失败、超时与环境错误；首次通过指第一次外部固定验收即通过。它不代表 Agent 内部从未修复。Agent 内部浏览器历次失败另外保留。
- 失败反馈给同一对话，最多按配置次数返工；旧验收结果和截图不可覆盖。每次外部验收使用新进程、新数据、新浏览器，避免旧模块缓存与上轮数据影响。
- 必要前置步骤失败后，依赖它的检查标为 blocked，不能把没有执行算成通过。超时的真实完成时间未知，completionMs 保持 null，不把上限当成实际完成时间。
- 成功完成耗时的中位数只计算成功轮次，并同时展示全部轮次通过率、超时、失败和环境错误。小样本不代表统计显著；比较两次报告需要相同 suiteHash、提示词、模型/思考、时限、返工和页面模式，保留所有样本，避免顺序和提供者负载偏差。

输出在忽略的 `work/agent-benchmark/<批次>/`：`report.md` 供阅读，`report.json` 含原始指标，每轮保留会话、命令日志、隔离项目、各次固定验收结果与最终页面截图。中断和清理耗时单独体现在 elapsedMs，成功指标 completionMs 截至验收通过。
