# 框架操作协议与能力声明

## 插件操作

插件启停 `POST /api/plugins/:id/toggle` 和配置 `POST /api/plugins/:id/config` 接受可选 `operationId`（1–100 位字母、数字、下划线或连字符）。客户端请求层自动产生 UUID；服务端兼容未传编号的旧调用。返回原有插件快照并附加 `operation`：

```json
{"id":"example","kind":"plugin.configure","targets":["stats"],"status":"awaiting-client","phase":"awaiting-client","startedAt":0,"updatedAt":0}
```

状态为 `running / awaiting-client / succeeded / failed`，阶段为 `applying / awaiting-client / rolling-back / completed`。启停成功表示启用选择或切换流程完成；依赖等待、前端是否运行和功能验收仍需看插件状态，不能由 operation 成功推断。

`GET /api/operations/:id` 返回记录。发送原应用的 `X-Application-Session`，避免切换应用后混用状态。工作台 Agent 可调用 `workspace_operation_status({id, session})`。配置预览和单选组切换继续使用原有 token 确认协议；确认、拒绝、超时和恢复失败会更新同一记录。

记录仅在当前应用运行会话内保存，最多保留 128 条；先淘汰已完成记录。编号仍有记录时，相同请求共用结果或等待中的预览，不重新执行；同编号不同参数返回 `OPERATION_ID_REUSED`。未知、过期或重启后的记录返回 `OPERATION_UNKNOWN`，不构成重放授权，也不保证跨进程去重。

写请求及恢复响应中的 `pendingSwitch / pendingConfig / preview` 只属于返回的操作编号，且仅在等待页面确认时提供；不能用另一操作的 token 进行确认。`GET /api/plugins` 仍返回全局待确认状态，供页面展示。

客户端丢失写入响应时，先查询原编号：已成功则读取最新状态；仍等待页面确认则用同编号取回预览；未知则报告 `OPERATION_RESULT_UNKNOWN`。页面工具超时为 `PAGE_RESULT_UNKNOWN`。超时不代表操作未执行。业务内容写入、应用切换及热更新暂不使用这个操作日志。

工作台在调用页面启用工具前生成操作编号，页面透传到 HTTP 请求；超时错误保留同一编号，可配合原应用 session 查询结果。单选组回滚保留服务端错误码和操作记录，页面恢复提示仅补充到消息中。

## 结构化错误

HTTP、页面桥接及工作台 IPC 保留 `code / message / status / retryable / operationId`，兼容原 `error` 文本。Agent 的工具错误中包含这些字段。不要按中文文字或仅按 HTTP 409 判断错误种类。

常见码包括 `CONFIG_REVISION_CONFLICT`、`PLUGIN_CONFIG_PENDING`、`PLUGIN_CHANGE_PENDING`、`PLUGIN_DEPENDENTS_ACTIVE`、`CONFIG_CHANGE_REJECTED`、`CONFIG_RECOVERY_FAILED`、`PLUGIN_CHANGE_REJECTED`。`retryable` 表示排除当前原因后可以重新发起操作，不意味着自动重放原写请求；相同失败编号仍返回原失败。

## 能力由提供者声明

在插件 `package.json` 的 `cordis` 内添加可选 `capabilities`。服务必须已在本插件同侧 `provides` 中声明；旧插件可逐步补充，无需修改应用级注册总表。

```json
"capabilities": [{
  "service": "example", "side": "server", "description": "读取示例数据",
  "contracts": ["types/server.d.ts"],
  "examples": ["server.js"],
  "tests": ["test/server.test.js"],
  "lifecycle": ["订阅由 owner 管理释放"]
}]
```

契约、示例、测试路径相对声明插件；必须是真实文件，不能越界或指向 dist/node_modules。构建和开发发现校验引用；正式运行允许只安装清单与 dist，因此不要求开发源码存在。生命周期文字是提供者契约说明，不代表框架能自动证明实现符合说明；tests 指向验证入口，也不表示已经执行或通过。

`workspace_development_info` 的 `capabilities` 精简索引自动列出所有已声明能力（key、provider、description），传 `capability:"server:example"` 可直接取回契约正文、示例和生命周期说明。它与 task/template 互斥。原 task/template 仍负责场景组合；默认展开场景及提供者声明的全部相关契约和示例正文，包含示例清单及实现。`includeRelatedSources` 默认 true；显式 false 才收窄为使用契约与单个示例，此时 `relatedSources` 列出省略路径，`expandSources` 可恢复完整资料。`includeAllProviders:true` 只扩大服务索引。按 capability 查询时返回详细 selectedCapabilities，多个同名提供者同时列出，不猜测应使用哪一个。

`GET /api/capabilities` 返回当前应用的声明与提供者运行状态。服务端能确认后端提供者状态，前端未核对时为 `unknown`，不能宣称页面已运行。索引不代表功能测试通过。由 `pnpm docs:capabilities` 生成的人类可读索引见 [插件能力索引](插件能力索引.md)，测试会检查它是否过期。

笔记的 notebook、notes、shell、noteFormats，以及灵感画布的 canvasSession、canvasDocuments、canvasUI 已接入。其他服务保留原有开发导航，按需迁移。该协议不改变 Cordis 的依赖注入、资源释放和业务服务所有权。
