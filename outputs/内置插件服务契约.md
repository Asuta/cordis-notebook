# 内置插件服务契约

适用于本项目的前端内置插件。`client/contracts.d.ts` 为 Cordis Context 和 Events 补充类型，`test/contracts.types.ts` 检查正确调用和应当被拒绝的错误调用。现有 JavaScript 项目不要求整体迁移到 TypeScript。第三方 API v1 包格式、安装与后端进程协议保持原样。

## 1. 服务负责业务与注册，插件负责自己的生命周期

内置清单在 `src/builtins.js` 声明 `requires.client`，宿主转换为 Cordis `inject`。使用 `ctx.notebook` 的插件必须声明 `notebook`，挂载界面的插件必须声明对应的 `shell` 或 `noteListUI`。

```js
export default function (ctx, sdk) {
  const input = sdk.el('input', { type: 'search' })
  ctx.noteListUI.mount(ctx, 'filters', input)
  const filter = ctx.notebook.registerFilter(ctx, 'my-search', () => true)
  sdk.listen(input, 'input', () => {
    const query = input.value.toLowerCase()
    filter.update(note => note.title.toLowerCase().includes(query))
  })
}
```

过滤器的存储不暴露给消费者；同一所有者不能重复注册同名过滤器，不同所有者可以使用相同名称。所有过滤器按“同时满足”组合。`update()` 替换当前规则，`dispose()` 提前注销；消费插件停用时自动注销。已释放的句柄不能再次更新，也不能删除后来注册的过滤器。

`notebook.current()` 返回只读副本，`visible()` 返回过滤排序后的只读笔记副本。通过 `edit({title, content, pinned})` 编辑，通过 `flush()` 等待保存完成。界面可调用 `notebook.observe(ctx, render)`，立即渲染一次，再订阅变化；监听随 ctx 自动清理。

## 2. 业务事件使用 Cordis

| 事件 | 参数 | 语义 |
| --- | --- | --- |
| `notebook/changed` | `{reason, selectedId, dirty, busy}` | 编辑、选择、筛选或保存状态变化。`observe()` 使用此事件。 |
| `notebook/before-save` | 只读 Note | 串行、可异步的保存前校验。返回提示文字或抛出错误即可拒绝；返回 undefined、null 或 false 表示通过。 |
| `notebook/saved` | 后端实际返回的只读 Note | PATCH 保存成功后通知；传递该次已保存版本，不保证仍是当前正在编辑的版本。 |
| `plugins/before-stop` | StopRequest | 本页面受管理的停止准备，可异步、可拒绝。 |

`Note` 包含 `id/title/content/pinned/createdAt/updatedAt`，时间为字符串。保存校验使用 `ctx.serial`，第一个拒绝终止后续校验；被拒绝时不提交 PATCH，脏状态和浏览器草稿均保留。

```js
ctx.on('notebook/before-save', note => {
  if (note.title.length > 100) return '这个插件要求标题不超过 100 个字符'
})
ctx.on('notebook/saved', note => {
  preview.textContent = note.content.slice(0, 120)
})
```

变化和成功通知使用 `ctx.parallel` 隔离监听器异常，异常会提示，但不会把已经完成的磁盘保存标记为失败。通知不等待监听器完成，因此不能用于阻止保存。保存前校验不要再次调用 `flush()`，否则会等待自身正在进行的保存。`notebook/saved` 当前覆盖本页笔记服务的 PATCH 保存，不是跨页面、后端 RPC 或创建/删除操作的全局审计事件。浏览器 DOM 点击、输入仍使用正常 DOM 事件。

## 3. 准备停止与资源清理分开

本页面管理器执行停用、前端重载或主题切换的流程：

1. 发出 `plugins/before-stop`，串行等待准备监听器。
2. 笔记服务锁住编辑、新建与选择，等已有业务操作结束，再保存草稿。
3. 全部通过后才发起后端变更或前端重载，并等待本页生命周期同步。
4. 无论成功、拒绝还是请求失败，都逆序执行已登记的释放函数。

```js
ctx.on('plugins/before-stop', async request => {
  lockEditing()
  request.hold(() => unlockEditing()) // 必须在异步操作前登记
  await savePendingWork()           // 抛出错误取消变更
})
ctx.effect(() => () => {
  clearInterval(timer)             // 卸载仅做资源清理，不再尝试保存或拒绝
})
```

`request.reason` 为 `disable/reload/switch`，`targets` 是这次直接操作的插件 ID，不是整个依赖闭包。所有准备监听器均可检查自己的未完成工作；笔记服务保守地保护所有受管理停止。锁保持到变更动作结束；后续监听器拒绝或后端依赖保护拒绝时也会正确解锁。`hold()` 只可在准备监听器完成前调用。原有 `sdk.guard(callback)` 作为兼容入口转接到该事件，原有 `sdk.watch` 也仍可使用。

准备协议只约束发起操作的这个页面，不跨进程、跨标签页进行分布式提交。其他页面停用、直接 API 操作、服务崩溃或浏览器关闭仍可能导致直接卸载；此时不进行迟来的保存检查，不延迟资源清理，未保存内容依靠编辑时写入的浏览器草稿恢复。浏览器存储不可用时会提示。该协议不是 Cordis dispose 的否决钩子。

## 4. 可运行的消费者示例

「保存后摘要」默认关闭，在插件管理器中开启后，正文保存成功会在页面下方显示最近保存的摘要。它只通过 `shell.mount(ctx, 'panels', node)` 挂载界面，以及 `ctx.on('notebook/saved', ...)` 监听事件。停用后节点与监听器自动清理，重新启用从等待下一次保存的状态开始。

源码为 `client/plugins/note-summary.js`，新增此插件只需要登记内置清单，无需修改管理器或保存逻辑。`test/notebook-contracts.test.js` 覆盖过滤器生命周期、校验失败、异步保存期间继续编辑、停止保护、强制卸载和摘要插件重复启停。
