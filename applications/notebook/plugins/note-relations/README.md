# 页面关系

所有笔记格式共用可选 `parentId`：省略或 null 表示顶层，字符串指向已有笔记。最多嵌套 12 层，禁止移动到自身或后代中；校验整棵树以防移动一个子树后超深。删除父页面只删除该篇，将直接子页面提升到祖父页面，并递增这些子页面的版本，避免旧页面静默覆盖。

发生保存冲突时「另存为副本」创建顶层副本，避免父页面已被其他标签删除后无法抢救草稿；保存后可再调整父页面。

恢复浏览器草稿时同样校验整个页面树。父页面已删除、移动后产生循环或超过深度时，保留草稿正文，暂用该页已保存的父页面关系显示，并提示另存为顶层副本。原草稿在副本成功保存前保留，继续编辑、再次刷新或复制失败均不会取消此恢复保护。

侧边栏显示可折叠页面树，打开深层页面时展开祖先。筛选结果自动展开，父页面被过滤时匹配的子页面仍显示。现有平面拖动排序适用于无子页面的列表；层级调整通过「更多笔记操作 → 页面关系 → 父页面」。该对话框还可创建任意已启用格式的子页面，并显示向外引用、反向引用和子页面；编辑区下方提供祖先路径导航。

BlockNote 输入 `@` 选择页面，在正文里存为 `{type:'pageLink',props:{noteId:'稳定ID',title:'插入时标题'}}`。显示时优先读取目标当前标题，删除后显示失效提示。旧快照标题用于目标不存在时的提示和派生纯文本。只扫描格式声明的真实引用，不把普通文本里的页面名称当作引用。

Agent：

- `notebook_create({type:'blocknote',title:'子页',parentId:'父页ID'})`。
- `notebook_read` 后使用 `notebook_update({id,revision,patch:{parentId:null}})` 移回顶层，或指定父页 ID。
- `notebook_page_relations({id?})` 返回路径、子页、向外引用、反向引用。
- 在 `notebook_blocknote_edit` 的插入/更新操作里使用上述原生 `content` 引用；操作仍遵守 revision 和整批校验。

格式插件可声明纯函数 `references(note)` 返回目标 ID 数组、`remapReferences(note,ids)` 返回该格式声明的数据字段。服务端备份恢复与前端关系查询共用这些钩子；层级数据由 notes/notebook 维护，插件不直接写其他插件文件。
