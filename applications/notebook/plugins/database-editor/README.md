# 数据库、自定义字段与命名视图

新建菜单选择“数据库页面”。直接子页面就是记录，每条记录可以打开编辑正文；支持所有已启用笔记格式。状态（未开始、进行中、已完成）、最多20个标签、可选日期属于页面公共 properties，移动、备份和恢复都保留。

表格和看板展示同一批页面。看板拖动或状态菜单更新状态；“编辑属性”修改标题、状态、标签、日期和自定义属性。“新增记录”不会离开数据库。表单保存失败保留输入，未保存修改会阻止切换页面、Agent 写入和插件停用；取消显式放弃编辑。

## 自定义字段

“新增字段”支持文本、数字、单选、多选、复选框、日期、链接，共七种类型。最多 32 个字段，单选/多选最多 50 个选项。字段使用稳定的 `f_` 开头 ID；值保存在真实记录的 `properties.custom`。同一字段改名不改变值。null 清空单个值，部分更新保留其他属性。

“管理字段”可改名、改类型、改选项和删除。不兼容的类型或选项变更会被前后端拒绝，检查范围包含数据库记录模板。删除字段会移除引用它的筛选/排序；原属性值仍保留在记录、历史和备份中，不做不可逆清理。记录移出数据库时也保留这些值。每篇记录最多保留 128 个自定义键。

## 命名视图

默认提供“表格视图”和“看板视图”，可新增、改名、删除，保留 1–20 个视图。每个视图保存布局、搜索词、状态/标签/日期筛选、自定义属性筛选和排序方向。属性筛选按 AND 组合；数字/日期支持范围比较，文本和多选支持“包含”；零与 false 不作为空值。

临时筛选会显示“尚未保存”。点击“保存视图”持久化，或“新建视图”另存；刷新、切换视图或离开编辑器会丢弃未保存的临时筛选。字段/视图/属性表单的未保存输入则有离开保护。表格/看板都支持按字段排序，看板分组仍固定为三种状态。

## 正文内嵌

BlockNote 输入 `/` → “数据库视图”，选择已有数据库。引用保存 `{type:'databaseView',props:{databaseId,viewId}}`，不复制记录。多个页面修改同一记录会同步显示；内嵌选择视图只修改该引用，不改变数据库页面的默认视图。保存某个命名视图的筛选会影响所有引用该视图的位置。数据库或视图删除后显示失效提示；停用数据库编辑器时 BlockNote 正文继续可用，引用显示启用提示。

JSON 备份包含源数据库、记录及引用，并在恢复时重映射 databaseId；HTML 保留引用标记，单独导出 HTML/Markdown 不打包数据库内容。模板使用方法见 [模板库](../note-templates/README.md)。

## Agent 与服务

- `notebook_create({type:'database'})` 创建；`notebook_database_read({id,viewId?})` 返回数据库的数值 revision、fields、views 和筛选后的记录。可用参数临时覆盖保存的筛选。
- `notebook_database_configure({id,revision,fields?,views?,activeViewId?})` 修改配置。fields/views 提交完整数组；省略的数组保留。字段 ID 保持稳定；删除字段时也要删除相关规则。不要用旧的 `{version:1,view:'table'}` 整体覆盖已有配置。
- `notebook_database_write({databaseId,action:'create'|'update',rowId?,revision?,title?,properties?})` 写记录；update 需要记录自身的 revision。custom 必须使用已定义字段 ID，非法值或旧版本不部分写入。
- `notebook_blocknote_edit` 可插入 databaseView 块，只传 props，不传 text/content。
- `databaseSchema` 由 format-database 提供纯数据契约；`databaseUI.View` 由 database-editor 提供共享组件。编辑器之间通过服务调用，不互相导入实现文件。

尚无计算公式、数据库关联与汇总、日历/时间线/画廊视图和自定义看板分组。父页面关系决定成员资格，因此删除数据库会将记录提升到上级，恢复数据库不会擅自重新移动这些记录。
