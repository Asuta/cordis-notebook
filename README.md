# 留白 · Cordis 插件笔记本

本地、单用户的网页版笔记本。前端与后端分别使用真实的 Cordis Context 管理插件。除启动、HTTP 传输、安装管理与恢复界面外，笔记本功能均由可停用插件提供。

## 接手与开发文档

第一次接手项目，先读 **[项目接手与维护指南](docs/项目接手与维护指南.md)**。包含快速启动、架构图与源码地图、插件生命周期、配置与主题切换流程、可复制的内置插件示例、API、数据备份恢复、测试和故障排查。

- [内置插件服务契约](docs/内置插件服务契约.md)：查阅公开服务、业务事件、停止准备协议及配置 SDK。
- [React 界面插件开发指南](docs/React界面插件开发指南.md)：React/shadcn 接入、服务依赖、生命周期与构建。
- [第三方插件开发指南](docs/插件开发指南.md)：开发、打包和安装现有 API v1 插件。

- [Workspace 插件开发指南](docs/Workspace插件开发指南.md)：插件自声明、自动发现、通用构建与公开类型归属。

## 启动

需要 Node.js 22+ 与 pnpm。

```sh
pnpm install
pnpm start
```

打开 http://127.0.0.1:3210 。`pnpm dev` 先构建，再监视后端导入图；插件运行入口是 dist，修改源码、JSX 或样式后须运行 `pnpm build`，重启服务并刷新页面。内置客户端插件以独立 ES 模块加载。`PORT` 可修改端口。`pnpm test` 运行集成测试。

## 使用

- 笔记格式由独立插件注册：「普通笔记格式」「自由页面格式」「Markdown 笔记格式」分别提供默认数据、校验、正文提取和编辑器关联。「新建」菜单自动显示已注册格式。停用某种格式会隐藏新建选项，保留已有笔记和数据；重新启用后恢复编辑。
- 新增格式的步骤与接口见 [笔记格式插件开发指南](docs/笔记格式插件开发指南.md)。本次协议面向内置插件，第三方 API v1 的后端格式注册尚未接入。

- 「新建」可选择普通笔记、自由页面或 Markdown 笔记。自由页面标题固定，纸张向右、向下延伸，用滚动条浏览；单击空白处或点击「新建容器」开始书写。
- Markdown 编辑器支持源码与预览分栏、仅编辑、仅预览三种视图，提供标题、粗体、斜体、列表、引用、代码块和链接插入按钮；Ctrl/Cmd+B、I 插入粗体、斜体，Ctrl/Cmd+Z 撤销。支持表格、删除线和任务列表；任务状态在源码中修改，预览复选框只读。
- Markdown 自动保存和草稿恢复保留原始源码，搜索、摘要、字数统计及 TXT 导出使用提取后的正文。「导出 .md」输出原始源码，不自动添加独立的笔记标题；JSON 导出保留全部数据。源码最多 200000 个 JS 字符，关闭拼写检查；原始 HTML 显示为文本，不执行。暂不提供公式、图表和代码语法高亮。
- 文字块顶部手柄用于移动，右边缘用于调整宽度，高度随内容增长；拖到视口边缘会自动滚动。手柄支持方向键微调，Shift 加速。
- 自由页面支持删除文字块、撤销/重做（Ctrl/Cmd+Z，Ctrl/Cmd+Shift+Z 或 Ctrl/Cmd+Y），以及自动保存、草稿恢复、搜索和字数统计。历史最多 80 步，仅在当前编辑器实例内保留；刷新或重载编辑器会清空历史。按笔记保存本标签页的滚动位置。
- 自由页面的 TXT 导出只保留按从上到下、从左到右排列的文本；「导出页面 JSON」保留文字块坐标和宽度，目前没有 JSON 导入界面。富文本、表格、图片、容器合并与拆分、框选、平移和缩放详见 [自由页面设计与使用](docs/自由页面设计与使用.md)。JSON 不内嵌图片，备份时需同时复制数据目录下的 note-assets 文件夹；暂不支持手写、.one 文件互通或格式原地转换。

- 页面右上角「插件管理」可实时启停插件，不需要刷新。
- 管理页面支持「卡片视图 / 依赖树」切换并记住偏好。依赖树从基础插件向依赖方展开，共享依赖以引用节点表示；选中节点可查看直接依赖、间接影响并执行原有启停操作。
- 自带 28 个内置插件：24 个基础功能与界面插件、可选的「保存后摘要」，以及苔绿、晴蓝、墨夜三套主题。默认启用基础功能和苔绿主题；摘要可在管理器中手动开启。
- 三套内置主题属于同一个单选组，点击「使用此主题」自动停用旧主题并立即切换界面；「恢复默认样式」停用当前主题。卡片显示当前选择，依赖树详情显示同组候选。
- 主题切换在后端和发起操作的页面均成功后才保存选择；启动失败、页面加载失败或 20 秒内未确认会恢复旧主题。切换期间串行处理，重启恢复已确认的选择。
- 前端通过 SSE 获取插件状态变化，只挂载或卸载变化的部分。
- 「启用」是用户配置；「运行中 / 等待服务 / 失败」来自 Cordis Fiber 的真实生命周期。卡片分别显示后端与当前页面前端的状态。缺少服务时保留启用选择，服务恢复后自动激活。
- 内置插件分别声明前端、后端的 `requires` / `provides` 服务；`dependencies` 只表示插件包依赖。服务名决定实际激活，启动顺序不再按内置插件 ID 递归安排。
- 布局提供 `shell`，列表提供 `noteListUI`，笔记 API 提供前端 `notesApi`。搜索、置顶等通过服务声明界面扩展依赖，扩展节点和监听器随消费插件卸载清理。详情区区分实际服务绑定与尚未绑定的候选提供者。
- 搜索和置顶通过 `notebook.registerFilter(ctx, key, predicate)` 注册过滤器，更新、注销和停用清理都走公开接口。笔记变化、保存校验和保存成功通过 Cordis 业务事件扩展。
- 依赖仍在使用时，停用被阻止并显示依赖方。先停用依赖方，再停用基础插件。
- 本页面发起停用、前端重载或主题切换时，先执行 `plugins/before-stop` 准备协议。保存失败会取消操作；准备成功后保持编辑锁，直到变更及本页同步完成。资源卸载只负责清理。浏览器在编辑时备份本标签页草稿；其他页面停用或服务异常消失无法被本页否决，通过草稿恢复。
- 管理入口不依赖布局插件，布局关闭后仍可恢复应用。
- 保存失败时可点击保存状态重试；Ctrl/Cmd+S 手动保存。
- 支持配置的插件显示「设置…」，卡片和依赖树详情都可进入。表单由插件声明生成，提供校验、恢复默认值和跨页面冲突提示；编辑中的表单不会被状态刷新覆盖。
- 「保存后摘要」可设置 80 / 120 / 200 字及是否显示字符数；「字数统计」可设置是否包含空格、换行，两者即时生效。「前端笔记服务」可设置 100–10000 毫秒自动保存间隔，保存草稿后重载服务和依赖界面，并保留当前笔记选择。
- 已开启插件的配置先在发起页面应用，确认成功后才写入磁盘并同步其他页面；应用失败会重新应用旧配置，20 秒未确认会取消。停用时也能保存配置，下次启用生效。

## 安装第三方插件

在「插件管理」选择 `.cordis-plugin.json` 文件，确认完全信任后安装，再手动启用。

自带样例：`outputs/local-lab.cordis-plugin.json`。启用「本机能力实验室」后，页面下方出现独立面板。点击运行，会写入并读回插件专属目录中的 hello.txt，执行 `node --version`，读取笔记数量。源码位于 `examples/local-lab/`。

```sh
node scripts/pack-plugin.js examples/local-lab outputs/local-lab.cordis-plugin.json
```

插件开发接口和完整示例见 [第三方插件开发指南](docs/插件开发指南.md)。

内置插件的公开服务、业务事件、停止准备协议和类型声明用法见 [内置插件服务契约](docs/内置插件服务契约.md)。`pnpm typecheck` 校验这些公共类型的使用示例；`pnpm test` 同时运行类型检查与运行时回归测试。

## 数据与迁移

- 笔记继续使用原来的 `data/notes.json`，无需格式转换。
- 插件启停配置：`data/plugins-state.json`。
- 插件设置与版本号：`data/plugins-config.json`，只存已确认的设置，不改变旧启停文件格式。
- 已安装插件代码：`data/plugins/<id>/`。
- 插件专属数据：`data/plugin-data/<id>/`。
- 停用、卸载都保留专属数据。清理数据是独立操作，要求先停用并输入插件 ID；只删除专属目录，不撤销插件在其他位置写入的文件。
- 备份整个 `data/` 可保留笔记、插件与配置。不要同时启动两个服务进程操作同一个 data 目录。

## 架构

每个内置插件都是 plugins/<id>/ 下的 pnpm workspace 包，package.json 的 cordis 字段声明身份、前后端入口、服务依赖、配置、公开资源与构建任务。server/plugin-discovery.js 只读清单；宿主根据持久化启用选择登记 Cordis Fiber，服务依赖满足后才导入后端。新增普通插件不再修改注册表、类型总表或专用构建逻辑。

```text
packages/host/          通用 SDK、配置与生命周期类型；前后端服务映射
client/host/            浏览器宿主、管理和同步
client/contracts/       通用宿主类型的兼容转发
server/host/            后端宿主、安装管理与第三方 worker
server/plugin-discovery.js 清单发现与校验
server/builtins.js      通用发现结果的兼容入口，无业务注册项
plugins/<id>/          包清单、前后端实现、公开 types 和私有辅助模块
plugins/<id>/dist/     构建产物；只按 public 白名单提供浏览器资源
scripts/plugin-builder.js 通用 bundle / copy / tailwind 执行器
scripts/export-plugins.js 导出仅含清单和 dist 的插件运行包
shared/                宿主共用协议实现
docs/                  架构、接手与开发指南
```

代码包依赖通过 package.json dependencies 声明，服务依赖通过 cordis.requires 声明。安装代码不会自动启用服务。浏览器和 Node 各有独立 Cordis Context；业务通过 ctx 服务协作，类型允许通过其他插件的公开类型导出引用。ClientContext 与 ServerContext 分开，宿主不汇总业务接口。

浏览器通过 /builtin/<id>/<资源路径> 获取显式公开的 dist 产物。后端入口、未公开文件和源码不能通过此路径读取。React/React DOM 由 UI 插件统一打包，其他视图从 ctx.ui 获取组件及 hooks；跨插件运行时实现导入由构建器拒绝。

界面挂载点由提供者插件注册；业务插件拥有自己的 CSS 和 Tailwind 构建，styles 清单负责自动加载与卸载。插件分类、图标和通用互斥组也在清单中声明，管理器不再维护业务分类列表。

前端、后端及双端内置插件共用配置确认流程，支持 live/restart 和失败恢复。后端取得独立的 runtime.dataDir；原有笔记、图片和配置路径保持兼容。运行阶段只需要插件清单与 dist；`pnpm export:plugins <新目录>` 导出运行包，在输出目录安装依赖后，用 PLUGINS_DIR 指定目录并执行 `pnpm start:runtime`。完整步骤及宿主文件要求见 [Workspace 插件开发指南](docs/Workspace插件开发指南.md)。

第三方 API v1 仍使用本地 JSON 安装包，由 server/host/remote.js 启动独立 Node 进程，经 IPC/RPC 协作；没有纳入本次 workspace 清单和运行包安装协议。

## 第一版边界

- 完全信任模式，没有操作系统安全沙箱。后端拥有当前系统账户权限，前端与宿主在同一页面执行。恶意前端可卡住页面，任意直接启动且脱离跟踪的进程不能保证被清理。
- 安装校验防止意外路径逃逸，不是对插件代码的安全审计。
- 支持本地自包含 JSON 插件包，最大 2 MB / 100 个文本文件，API 版本固定为 1。外部依赖应预先打包进入口，Node 内置模块可直接导入。安装不执行 npm/pnpm 脚本。
- 不提供插件市场、签名验证、覆盖升级、自动更新与数据库迁移回滚。更新时先停用并卸载旧代码，再安装新版，数据保留。
- 第三方 API v1 保留按插件 ID 检查和原有 SDK 的兼容路径；本次服务契约改造用于内置插件。尚无依赖版本范围解析。
- 配置系统支持内置前端、后端及双端插件；第三方 API v1 暂不接入。发起页面确认成功不代表所有打开的页面都能应用成功；其他页面通过 SSE 同步并显示自己的运行状态，依赖重载时未保存内容通过本标签页草稿恢复。
- 停用不能撤销已经发生的文件修改、外部网络请求或命令效果。
- 多标签页编辑同一笔记仍以最后保存为准，未实现协同合并。
- Cordis 固定为 4.0.0-rc.10；前后端使用同一个依赖版本。
